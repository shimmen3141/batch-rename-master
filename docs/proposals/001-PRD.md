# 柔軟な一括リネームアプリ 仕様・要件定義書

## 1. プロジェクト概要
* **目的:** 複数のファイルに対して、プレフィックス、サフィックス、連番、日時などを柔軟に組み合わせた一括リネームを、直感的かつ安全に行えるようにする。
* **ターゲットプラットフォーム:** Android（主目標）、Windows
* **技術スタック:** Flutter

## 2. アプリの基本フロー（ユーザー体験）
Androidの権限仕様（SAF）と、直感的な操作性を両立するための基本フローです。

1.  **フォルダ権限の取得（OS標準UI）:** アプリ起動後、OS標準のファイルピッカーを呼び出し、作業対象となる「フォルダ」を指定させ、読み書き権限を取得する。
2.  **ファイルの選択と並び替え（独自UI）:** 取得した権限を用いてフォルダ内を読み込み、アプリ独自のリストUIを展開。ユーザーはチェックボックスと並び替え機能を使って対象を絞り込む。
3.  **命名ルールの構築（独自UI）:** トークン（ブロック）を組み合わせて新しい名前のルールを作る。
4.  **プレビューと実行:** リアルタイムで変更後の名前を確認し、安全機能（ドライラン）を通過した上で一括リネームを実行する。

## 3. 画面構成とUI要件
基本は**「1画面（メインのワークスペース）＋ オーバーレイ（ルール構築）」**の構成とし、複雑な画面遷移を避けます。

### 3.1 メイン画面（ワークスペース・ファイルリスト）
* **リスト表示:** 読み込んだファイルの一覧を表示。左側に「現在のファイル名」、右側に「変更後のファイル名（プレビュー）」を並べる。
* **選択（チェックボックス）:** * 各ファイルにチェックボックスを配置。
    * デフォルトは「全選択」状態（または全解除状態）。
    * チェックが入っているファイルのみがリネーム対象となり、プレビューが更新される。連番もチェックされたファイルの上から順に振られる。
* **ソート（並び替え）機能:**
    * リスト上部に「名前順」「作成日時順」「サイズ順」の切り替えボタンを配置。
    * **カスタム順（シームレスな移行）:** リストの各アイテムにドラッグ用のハンドル（≡アイコンなど）を配置。ユーザーがアイテムをドラッグ＆ドロップで手動移動させた瞬間、ソート設定が自動的に「カスタム順」に切り替わる。
* **Windows固有要件:** エクスプローラーからのファイルのドラッグ＆ドロップ追加に対応させる。

### 3.2 ルール構築エリア
デバイスの画面サイズに応じて表示方式を切り替えます。
* **モバイル（Android）:** 画面下部から引き出せる「モーダルボトムシート（ModalBottomSheet）」。
* **デスクトップ（Windows）:** 画面幅に余裕がある場合は、右側に常時表示される「2ペインレイアウト」。
* **UI要素（トークン・ビルダー）:**
    * 構成要素を「トークン（Chipウィジェット等）」として扱い、追加・並び替え（ドラッグ＆ドロップ）を可能にする。
    * **用意するトークン:**
        1.  **[元のファイル名]**: 拡張子を除いたベース名。
        2.  **[自由テキスト]**: ユーザーが入力する固定文字列（例: `_`, `ファイル`）。
        3.  **[連番]**: 開始番号、桁数（ゼロ埋め）を指定。
        4.  **[日時]**: 基準（作成日時/更新日時/現在日時）と、フォーマット（例: `YYYYMMDD`）を指定。
    * トークンをタップすると、それぞれの詳細設定ダイアログが開く。

## 4. コア機能とロジック要件

### 4.1 リアルタイムプレビュー
* ルールの変更、ファイルのチェック状態の変更、並び順の変更が行われるたびに、即座にリスト上の「変更後のファイル名」を更新する。

### 4.2 安全対策・エラーハンドリング（ドライラン検証）
リネーム実行前に内部で検証を行い、ファイル名破損を防ぎます。
* **リアルタイム警告:** プレビュー生成時、重複するファイル名や、連番の桁数が不足している箇所を赤色文字や警告アイコン（⚠️）でハイライト表示する。
* **実行時のバリデーション:** 警告がある状態で「実行」ボタンが押された場合、処理を一時停止し、ダイアログを表示する。
    * **選択肢A「キャンセル」:** 実行を取りやめ、ルール修正に戻る。
    * **選択肢B「自動解決して実行（強制実行）」:**
        * 重複が発生する場合は、自動で末尾に `(1)`, `(2)` などを付与する。
        * 連番の桁数が不足する場合（例: 2桁指定で100番目になった場合）、自動で桁数を拡張して処理を続行する。

## 5. OS・権限仕様（Android向け最重要項目）
* **SAF（Storage Access Framework）の利用:** `MANAGE_EXTERNAL_STORAGE`（すべてのファイルアクセス権限）はPlayストアの審査リスクが高いため**要求しない**。
* 代わりに、ユーザーに作業したい「フォルダ単位」でのアクセス許可（`READ_EXTERNAL_STORAGE` および `WRITE_EXTERNAL_STORAGE` に相当するSAFのURI権限）を取得する。
* これにより、リネーム（書き込み）実行時に、ファイル1つ1つに対するOSの確認ダイアログが表示されるのを防ぎ、一括処理をシームレスに行う。
