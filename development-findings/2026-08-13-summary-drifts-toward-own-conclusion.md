# Development finding: 転記をやめても、要約する時点で自分の結論へ寄っていた

- 観測日: 2026-08-13
- 観測した作業: `013:T02`。Google Playのpolicyの「invalid uses」を要約する際、限定語を3箇所とも自分に有利な向きへ動かした
- 改善先: Agentの実行。**先行findingの対処が不十分だったことの記録**でもある
- 関連: [`2026-08-13-summarizer-paraphrase-labeled-as-primary-source.md`](2026-08-13-summarizer-paraphrase-labeled-as-primary-source.md)、`specs/013-safe-android-rename/`

## 観測した事実

`013:T01`で、同じ根本原因(加工したものを原文として提示する)のFAILが**3回続いた**。人間の判断で**外部資料の引用を全廃**し、「出典のURL+自分の言葉での要約+原文ではない旨の明示」へ移した。attempt 4はPASSした。

**その次のtaskで、4回目が出た。** 今度は転記ではなく**要約**である。

Playの「invalid uses」について、原文は次の構造を持つ。

- 認められない例として `Any File selection activity where the user manually selects individual files` を挙げる。**`Any`であり、限定語は無い。**
- 「推奨される代替」の表に、`User selects files for importing/transferring/processing` に対してSAFを検討せよ、という行がある。
- 列挙の末尾に `Note: This list is not exhaustive.` が付く。

筆者が書いた要約は次のようになっていた。

- 「利用者が個々のfileを手で選ぶ**だけ**の file選択操作」— **原文に無い限定語を足した。** 「選ぶだけのapp」に狭めると、改名するこのappは対象外に読める。
- 代替表の `processing` の行を**落とした**。一括改名はprocessingに読めるので、**ページ中でこのappに最も不利な記述**である。
- 「一覧は網羅的でない」を、invalid usesの**反証側**に置いた。原文ではinvalid usesの列挙に付いた注記で、**invalidの範囲を広げる方向にしか働かない。**

**3箇所とも、自分の結論(候補Eを採用してよい)に有利な向きだった。** その結果「残る不確実性は『審査に通るか』であって『該当しうるか』ではない」という、原文から導けない結論を4つのfileへ書いた。

独立reviewが原文を取得して検出した。

## なぜ「引用の全廃」で止まらなかったか

引用の全廃は**転記ミス**を消した。実際、逐語の誤りは出ていない。

しかし**バイアスは転記ではなく解釈の側にあった。** 要約は「何を残し何を落とすか」の連続で、そこには必ず筆者の関心が入る。**自分が支持している結論があるとき、不利な情報は「重要でない」と見えて落ちる。** 悪意ではなく、選別の基準が結論に汚染される。

`AGENTS.md`の「同じ根本原因が2回続いたら手段を変える」は、`T01`で発火して手段を変えた(転記をやめた)。**変えた手段が原因の一部しか覆っていなかった。** 原因は「加工」ではなく「**自分に有利な向きの加工**」で、転記も要約もその媒体にすぎない。

## 影響

- 独立reviewが1回。`T02`の`spec.md`が`approved`から`draft`へ戻り、再承認が必要になった。
- **人間へ渡す判断材料が歪んでいた。** 「該当しうるかは解決した」と報告したが、解決していない。人間がrisk受容を判断する前提が誤っていた。**これが最も重い。**
- 結論(候補Eの採用)は変わらない。ただし**riskは当初の見立てより大きい**ことが分かった。

## 仮説と提案

- **自分の結論に有利・不利で情報を分類してから書く。** 不利な項目を先に列挙し、それぞれに「落とさない理由」を確認する。今回落ちた3つはいずれも不利側だった。**偏りは方向を持つので、方向で検査できる。**
- **結論を左右する資料は、要約せず出典と節名だけを示して人間に読ませる。** `013:T02`の修正ではそうした。配布riskの受容のような**Agentが決めない論点**では、要約自体が越権に近い。
- **利害のある要約はreviewの必須項目にする。** 「筆者の結論に有利な向きへ限定語が動いていないか」は、reviewerが原文を取れば機械的に検査できる。今回はreviewerへ明示的に依頼して検出できた。**依頼しなくても見る工程にする価値がある。**
- 一般化: **手段を変えるときは、原因のどこまでを覆うかを言葉にする。** 「転記をやめる」は「転記ミス」を覆うが「解釈バイアス」を覆わない。覆わない範囲を明示しておけば、次の再発を予測できた。
