# 複製のずれ検査が、改行コードの違いで必ず FAIL する

0.7.1 で入った「CI へコピーしたスクリプトがプラグインの実体とずれていないか」の検査が、**貼り直した直後から FAIL のまま**になる。

## 症状

手順どおり `cp` で貼り直し、コミットした直後に:

```
$ asdd_config.py check
CI へコピーしたスクリプトが、プラグインの実体とずれている:
  - .github/scripts/run_plan_helper.py: プラグインの実体と内容が違う(貼り直す)
  - .github/scripts/project_plan_to_issues.py: プラグインの実体と内容が違う(貼り直す)
FAIL
```

何度貼り直しても直らない。

## 原因

`asdd_config.py` の比較が**バイト列の完全一致**:

```python
same = copy.read_bytes() == source.read_bytes()
```

一方、プラグインの実体は **CRLF**、リポジトリは `.gitattributes` に `* text=auto eol=lf` があるため、コミット時に **LF へ正規化**される。

```
run_plan_helper.py        : プラグイン 1181 CR行 / コピー 0 CR行
project_plan_to_issues.py : プラグイン  557 CR行 / コピー 0 CR行
改行を無視した差分         : 0 行(内容は完全に同一)
```

つまり**内容は一致しているのに、改行コードだけで不一致と報告される**。

## なぜ厄介か

- 検査が**常に FAIL** なので、「FAIL は貼り直し忘れの合図」という意味を失う。**本物のずれが起きても気づけない**(狼少年になる)
- 手順書どおりに作業した人が「貼り直したのに直らない」で止まる。実際に一度止まった
- `.gitattributes` で改行を統一しているのは正しい運用なので、プロジェクト側を直す話ではない

## 提案

比較を**改行コードに依存しない**形にする。最小の変更はこれ:

```python
def _norm(p):
    return p.read_bytes().replace(b"\r\n", b"\n")
same = _norm(copy) == _norm(source)
```

もし「バイト単位で同一であること」自体を保証したいなら、`cp` ではなく**改行を正規化して書き出すコピー用サブコマンド**を用意し、手順もそれに変えるのが筋(手動 `cp` を案内している限り、環境ごとの改行差は避けられない)。

## 補足: 印による再発防止の効き方(実測)

同時に確認した事実。0.7.1 の `- 書式: 2` は**次回の書式変更から**効く:

| 検証 | 結果 |
|---|---|
| **0.6 のコピー**が新書式(`書式: 2`)を読む | 落ちずに状態を空文字で返す(今回の事故と同じ) |
| **0.7 のパーサ**が未知の書式(`書式: 3`)を読む | `PlanFormatError` で落ちる ✅ |

古い側に印を見る処理が無い以上これは原理的な限界で、修正の不備ではない。ただし「もう安全」と読めると次で足をすくわれるので、移行手順に「**印は次回以降に効く。今回のずれはコピーの貼り直しでしか塞げない**」と書いておくと誤解が減る。
