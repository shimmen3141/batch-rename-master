# Development finding: reviewの指摘を直したが、同じ主張を持つ他のfileへ届いていなかった

- 観測日: 2026-08-13
- 観測した作業: `013:T01`。review attempt 1のP1を直したが、attempt 2で同じP1が別のfileに残っていると再指摘された
- 改善先: Agentの実行(修正の適用範囲)。ASDD側は`review-task`が範囲を検査できているので、穴は運用側
- 関連artifact: `specs/013-safe-android-rename/tasks/T01-decide-storage-boundary/research-matrix.md`、同`tasks/T04`・`T05`

## 観測した事実

review attempt 1が2つのP1を出した。

1. Playの許可条件を「閉じたallowlist」と書いていた(原文は開いた例示)。
2. `renameat2`のAPI 30という`[未到達]`主張が、無印の事実として書かれていた。

筆者はどちらも「直した」と報告した。実際に直したのは**指摘がfile:lineで名指ししたfileだけ**だった。

attempt 2が同じ2件を再指摘した。

- 1は`research-matrix.md`の103行目で直っていたが、**同じfileの236行目(結論節)に旧表現が残っていた**。読者が実際に着地するのはそちらである。
- 2は`research-matrix.md`・`ADR-002`・`T02`で直っていたが、**`T05`と`T04`に残っていた**。しかも`T05`は選択肢を2案で提示しており、3案へ直した当のpointを打ち消していた。

**同一taskで2回目のFAILである。** `AGENTS.md`の「3回FAILで自動修正を止める」まで残り1回になった。

## 期待していた動きと実際の動き

- 期待: 指摘を直せば、その主張はrepositoryから消える。
- 実際: 名指しされた箇所だけ消え、同じ主張の他の実例が残った。**部分的な修正は、矛盾という新しい問題を作る。** 103行目と236行目が正反対のことを言う状態は、直す前より悪い。

## 根本原因

**指摘をfile:lineの修正として扱い、主張の修正として扱わなかった。**

reviewerはP1を「この行が間違っている」と書く。それは指摘の**位置**であって**範囲**ではない。同じ主張がrepositoryの何箇所にあるかは、指摘されるまで分からないのではなく、**`grep`すれば分かる**。やらなかっただけである。

構造的に起きやすい条件も揃っていた。

- 同じ内容がplan、task、ADR、matrixへ**意図的に重複して書かれている**(ASDDは各文書が自己完結することを求める)。
- taskを7つ同時に定義した直後だった。**書いた直後の文書ほど、内容を覚えているつもりで読み返さない。**

## 影響とworkaround

- 影響: reviewが1回余分に回った。独立reviewは安くない工程である。
- 影響: 文書内に**自己矛盾**が生じた。片方だけ読んだ人が誤った理解をする。
- 影響: 3-FAIL規律の残り回数を消費した。
- workaround: attempt 3の修正では、訂正対象を**`grep`で全文横断してから**着手した。「限られる」「API 30」「f97a2cc」「透過」「(ext4)」など、**主張ごとに検索語を決めて**残存を確認した。

## 仮説と提案

- **指摘を受けたら、まず主張を検索語へ翻訳する。** 「Playの許可対象」なら「限られる / 次のみ / allowlist」。修正後に同じ検索を流して0件を確認する。**修正の完了条件は「その行を直したこと」ではなく「その主張がrepositoryに残っていないこと」。**
- **複数fileへ意図的に重複させた内容は、修正時も必ず複数fileへ届く**と最初から想定する。ASDDは重複を許す設計なので、これは設計の代償であって欠陥ではない。代償を払う側が対応する。
- reviewerへ渡すときに「同じ主張が他にもあるか探してほしい」と明示的に頼むと、attempt数を減らせる可能性がある。ただし**それはreviewerの仕事ではなく修正側の仕事**である。
- 一般化: **指摘は標本であって母集団ではない。** 1件見つかったら、同種が他にもあると考えて探す。

## 改善結果

attempt 3へ向けて、`grep`横断で次を解消した。閉じたallowlist表現(結論節)、API 30の無印主張(`T04`/`T05`)、`Evidence revision`の誤base(8 file)、生出力の非逐語提示、判定軸2の未観測主張。

単発なら実行上の問題だが、ASDDが自己完結のため重複を許す代償は共通規律に値すると再評価した。ASDD PR #10で、指摘を行単位でなく主張として横断検索し、修正後も再検索する規律を追加した。
