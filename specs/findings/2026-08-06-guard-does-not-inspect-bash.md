# 承認済み仕様のガードが Bash 経由の書き込みを見ていない

- **症状**: `hooks.json` の PreToolUse matcher は `Write|Edit|Bash` だが、`approved_spec_guard.py` に **Bash の payload** を与えると何も出力せず exit 0 になる(`tool_input.command` を見ていない)。実際、承認済みの `spec.md` 4本を `python3 - <<PY ... PY` のヒアドキュメントで書き換えたとき、確認は一度も出なかった。Edit ツールで同じファイルを触ると `ask` が返る。
- **どこで**: 0.6 移行の確認中。エージェントが複数ファイルをまとめて機械的に書き換えるとき、Edit ではなくスクリプトを使うのはごく自然な選択なので、**抜け道としては通りやすい**。
- **その場の回避**: なし(気づいた時点では書き換え済みだった)。以後、承認済み仕様に触るときは Edit ツールを使うことにした。
- **提案**: matcher に `Bash` がある以上、`tool_name == "Bash"` のときは `tool_input.command` から書き込み先を推定して(リダイレクト・`tee`・`sed -i`・ヒアドキュメント内のパス等)、承認済み仕様のパスが現れたら `ask` を返す。完全な解析は無理でも「パス文字列が現れたら確認」で十分に効く(誤検出は確認1回で済む)。
