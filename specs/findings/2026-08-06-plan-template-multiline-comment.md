# 計画テンプレートの2行コメントが、状態を draft と読ませない

- **症状**: `create-plan` のテンプレートどおりに `plan.md` を作ったところ、`run_plan_helper.py index` が新規計画を **`approved`** と表示した(実際は `draft`)。承認していない計画が承認済みに見えるので、**承認ゲートの見え方が壊れる**。
- **原因**: テンプレートの状態行のコメントが2行にまたがっている。

  ```
  - 状態: draft <!-- draft → approved(人間が変更)。これ以降の進行状態(in_progress/done)は
                     タスクの状態から導出されるので、ここには書かない -->
  ```

  `header_field()` は `^-\s*<label>\s*[:：]\s*(.+)$` で**1行だけ**を取り、そのあと `<!--.*?-->` を除去する。閉じタグが次の行にあるため除去に失敗し、値が `draft <!-- draft → approved(人間が変更)。…` という文字列になる。`derived_plan_status()` は `header_status == "draft"` の完全一致で判定するので不一致となり、`approved` 相当に落ちる。
- **どこで**: create-plan の手順3(テンプレートを元に plan.md を作成)。既存の計画は 0.4 の `migrate` が1行コメントに書き換えているため無事で、**新規作成でだけ踏む**。
- **その場の回避**: コメントを1行に畳んだ(既存計画と同じ形)。
- **提案**: テンプレート側のコメントを1行にする(最小)。あわせて `header_field` を複数行コメントに耐えるようにするか、`index` が「状態の値が語彙(`draft`/`approved`)に一致しない」ときに警告を出すと、同種の書式ずれを黙って通さずに済む。
