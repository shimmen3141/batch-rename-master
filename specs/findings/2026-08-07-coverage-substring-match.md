# coverage の被覆照合が、否定の注釈でも「覆われた」と判定する

- **症状**: `run_plan_helper.py coverage` は VER の成果物(ディレクトリ)配下のファイル本文に対して **ID の単純な文字列一致**で照合する。そのため「このファイルでは**扱わない**」という**否定の注釈**に ID を書いても、覆われた扱いになる。
- **どう踏んだか**: 005 T2 の実装中、`test/spec_005_rename_exec/execution_test.dart` の冒頭コメントに「巻き戻し(OP-003 / REQ-006 / REQ-007 / REQ-008)は T6 の範囲」と**担当外であることを明記**したところ、T6 が未着手にもかかわらず該当 5 ID の NOTE が消え、被覆されたように見えた。コメントから ID を外して修正し、修正後に当該 ID の NOTE が正しく再出現することを確認した。
- **なぜ危ないか**: 「ここでは検証しない」と正直に書くほど被覆が水増しされる。担当外を明記するのは良い習慣なので、**良い習慣が検査を壊す**関係になっている。今回は実装者が気づいたが、気づかなければ「T6 の要件は誰かが検証済み」と読める状態が残った。
- **その場の回避**: コメントから ID を外した(担当外の記述は ID を書かずに日本語だけで書いた)。
- **提案**: 完全な解決は難しいが、緩和案が3つある。(a) 照合対象を**テスト名・テスト宣言の行**に限定する(`test(`/`group(` の引数、あるいは `expect` を含むブロック)。(b) 否定を表す近傍語(「範囲外」「扱わない」「T\d+ の範囲」「対象外」)を含む行を照合から除く。(c) ID の出現行を報告に出し、**人間が見て気づける**ようにする。少なくとも (c) は安価で、どの行が根拠になったかが分かるだけでも誤検出に気づける。
