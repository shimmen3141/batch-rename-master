# 承認ゲートが、書き込み先ではなく「内容に現れた仕様パス」で差し戻す

- **症状**: `plan.md` を更新するスクリプトが差し戻された。書き込み先は `plan.md` だけだが、**書き込む内容**(新タスクの「変更対象」行)に承認済み契約のパス文字列が含まれていたため、契約への書き込みと判定された。

  形としてはこういうもの(書き込み先は plan.md のみ、契約のパスは本文として現れるだけ):

  ```
  detail = """### T8: 空ルール時の扱いの仕様更新
  - 変更対象: <承認済み契約のパス>、<spec.md のパス>
  …"""
  Path("specs/005-rename-exec/plan.md").write_text(...)
  ```

- **どこで**: run-plan で、**承認済み仕様を更新するタスクを計画に追加**しようとしたとき。「この仕様を変更するタスク」を計画に書くのはごく普通の操作なので、それなりの頻度で踏む。

  この finding 自体も同じ理由で一度差し戻された(本文に契約のパスを引用していたため)。記録すること自体が止まるので、気づきが残らない方向に働く。

- **その場の回避**: Write / Edit ツールで書いた(書き込み先が引数で明示されるので誤検出しない)。

- **関連**: 読み取り専用コマンドの誤検出は 2026-08-07 に修正済み(判定を「その仕様パスが書き込み先か」に変更)。今回はその判定が**ヒアドキュメント内の文字列**まで拾ってしまう残りのケース。

- **提案**: 書き込み先の推定を「書き込み構文の位置にあるパス」に限定する — リダイレクト先、`write_text(...)` / `open(..., "w")` の**引数**、`sed -i` / `tee` / `mv` / `cp` の対象。文字列リテラルとして本文に現れただけのパスは対象外にする。完全な構文解析は不要で、「引数の位置か、単なる本文か」を見るだけでこのケースは消える。
