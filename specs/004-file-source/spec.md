# ファイル読み込み(file-source) 振る舞い仕様

- Status: draft <!-- draft → approved(人間が変更) → deprecated -->
- Level: Light（正しさの正本は本ファイル）

## 目的（説明的・正誤判定には使わない）

実ファイルの読み込み入口を定義する。抽象ポート `FileSource` が「フォルダを開く」「ファイルを選ぶ」の2経路で `FileEntry` 群を返し、UI 側はそれを**1回で差し替えず「作業セット(かご)」へ蓄積**する。フォルダ/ファイル選択を繰り返して**別フォルダのファイルも混在**でき、各ファイルは**元場所ハンドル(URI/パス)**で一意に識別される(005 のリネーム書き戻し先)。純粋部分(ポート契約・作業セットの蓄積/重複排除・002 への結線)はサンドボックスで検証し、実 SAF/実ピッカーはホスト検証(実装は 004 T4)。

## 境界

- 対象（in scope）: `FileSource` ポートの契約(`pickFolder` / `pickFiles` と結果型 `PickResult`=`Picked`/`Cancelled`/`Failed`)、`FileEntry` の**元場所ハンドル**と**表示用の場所**、**作業セット**の操作(追加 / 除去 / 全消去 / ハンドルによる重複排除 / 既定選択)、選択結果を 002 の `FileListController` へ供給する結線、`Failed` 時のエラー通知。
- 対象外（out of scope）: リネーム実行=実ファイル書き込み(005)。命名エンジン(001)・リスト/選択/ソート/プレビュー(002)・ルール構築(003)の既存振る舞い。**画像の撮影日時(不変キー)と「すべて/アルバム」横断ギャラリー**(MediaStore/EXIF ベース)は後続の専用機能。サブフォルダ再帰探索。ストレージ/権限の具体実装(SAF・OS ピッカー・使用プラグイン)は `FileSource` 契約を満たす限り自由(実装は T4)。
- アクター: ユーザー(フォルダ/ファイルの選択・除去操作)、`FileSource` 実装(プラットフォーム)、`FileListController`(作業セットの保持)。
- 入力: ユーザーの選択操作 → `FileSource` が返す `PickResult`(`Picked(entries)` / `Cancelled` / `Failed(error)`)。
- 出力: 002 の作業セットに反映されたファイル群(表示順・選択状態・場所サブ情報・プレビュー)、`Failed` 時のユーザー通知。
- 永続化される状態: なし(セッション内の作業セットのみ。権限 URI の永続保持は実装内の詳細)。
- 外部副作用: 読み取りのみ(フォルダ列挙・メタデータ取得・権限取得)。書き込みなし。

## 振る舞い

### 操作（`FileSource` ポート契約）

結果は3値の直和 `PickResult` で表す(不正な状態を型で排除する):

- `Picked(entries)`: 選択が確定した。`entries` は 0 件以上(空フォルダは空の `Picked`)。各 `FileEntry` は元場所ハンドルを持つ。
- `Cancelled`: ユーザーがピッカーを閉じ、何も選ばなかった(決定していない)。
- `Failed(error)`: 選択後のアクセス・列挙に失敗した。`error` は理由(`permissionDenied` / `io` / `unknown`)+任意メッセージ。

| 操作 | 契約 |
|------|------|
| `pickFolder()` | ユーザーにフォルダを選ばせ、そのフォルダ内ファイルを読み込む。結果を `Picked` / `Cancelled` / `Failed` のいずれかで返す。例外を投げない(REQ-001/008)。 |
| `pickFiles()` | ユーザーにファイルを個別選択させ(複数可)、`Picked` / `Cancelled` / `Failed` のいずれかで返す。例外を投げない(REQ-001/008)。 |

### 操作（作業セット = 002 コントローラの拡張）

| 操作 | 契約 |
|------|------|
| `addFiles(entries)` | `entries` のうち**ハンドルが既存にない**ものを、与えられた順で末尾に追加する。既存ハンドルと一致するものは無視(重複追加しない)。追加分は既定で選択状態。空リストは無変化(REQ-004/005)。 |
| `removeFile(handle)` | `handle` に一致するファイルを作業セットと選択から除去する。一致が無ければ無変化(REQ-006)。 |
| `clearFiles()` | 作業セットと選択を空にする(REQ-006)。 |

### 要件

| ID | 優先度 | 要件（外部から観測可能な文で） | 検証 |
|---|---|---|---|
| REQ-001 | must | `pickFolder()` / `pickFiles()` は結果を `Picked(entries)` / `Cancelled` / `Failed(error)` のいずれかで返す(例外を投げない)。選択確定=`Picked`(空フォルダは空の `Picked`)、閉じて未選択=`Cancelled`、権限拒否・IO 失敗=`Failed`。 | VER-001 |
| REQ-002 | must | 各 `FileEntry` は安定した**不透明な元場所ハンドル**(SAF URI / ファイルパス相当の文字列)に対応づく。2つのエントリはハンドルが等しいとき同一ファイルとみなす(重複排除と 005 の書き戻しの基準)。 | VER-001, VER-002 |
| REQ-003 | must | 各 `FileEntry` は `name`・`modifiedAt`・`size` を持つ。004 は `createdAt` の取得を保証しない(SAF で取得不能)。よって 004 の時系列の基準は `modifiedAt`(=「更新日時」)であり、「作成日時」としては提示しない。 | VER-001 |
| REQ-004 | must | `addFiles(entries)`: ハンドルが既存に無いものだけを与えられた順で末尾へ追加する。既存ハンドルと一致するものは追加しない(重複しない)。空リストの追加は無変化。 | VER-002, VER-003 |
| REQ-005 | must | `addFiles` で追加されたエントリは既定で選択状態になる。 | VER-002, VER-003 |
| REQ-006 | must | `removeFile(handle)` は一致エントリを作業セットと選択から除去し、`clearFiles()` は両方を空にする。一致が無ければ無変化。 | VER-002 |
| REQ-007 | must | 結線: `pickFolder`/`pickFiles` が `Picked` を返したら `addFiles` で作業セットへ反映し、002 のリスト(件数・表示順)とプレビューに追加が現れる。追加は末尾(=追加順)で、初期ソートは `custom`(追加順)。以後の並びは 002 のソートに委ねる。 | VER-003 |

| REQ-009 | should | 各 `FileEntry` は**表示用の場所情報**(元のフォルダ)を持ち、002 の各行に**サブ情報**として表示される(作成/更新日時・サイズと同格の副題。同名ファイルの見分けにも役立つが、同名に限らず常に表示)。表示用の場所は人間可読の文字列で、識別用の不透明ハンドル(REQ-002)とは別物でよい。 | VER-003 |

### 代表例

| # | 入力/操作 | 期待 |
|---|---|---|
| 1 | fake `pickFiles()` が [a,b] を返す → `addFiles` | 作業セット=[a,b]、両方選択 |
| 2 | 続けて fake `pickFolder()` が [b,c] を返す(b は同ハンドル) → `addFiles` | 作業セット=[a,b,c](b は重複追加されない)、c は選択 |
| 3 | `pickFiles()` がキャンセル=[] → `addFiles([])` | 作業セット不変 |
| 4 | `removeFile(bのハンドル)` | 作業セット=[a,c]、選択から b も除去 |
| 5 | `clearFiles()` | 作業セット=[]、選択=空 |
| 6 | 別フォルダの [a,d](a と別ハンドル) を続けて追加 | 混在して蓄積(a,c,... の後ろに d)。同名でもハンドルが異なれば別ファイル |
| 7 | fake `pickFolder()` が `Cancelled` を返す | 作業セット無変化・通知なし |
| 8 | fake `pickFolder()` が `Failed(permissionDenied)` を返す | 作業セット無変化・**ユーザーにエラー通知**(005 の命名警告とは別チャネル) |
| 9 | 場所付きの a を追加 → 002 の行を見る | a の行に場所(フォルダ)がサブ情報として表示される |

## 波及: 001/002 の承認済み仕様の更新（実装前に人間の再承認が必要）

本機能は既存の承認済み仕様の外部振る舞いに触れる。004 T2 以降の着手前に、各仕様を更新し人間の再承認を得る(黙って変更しない):

- **002-file-list**: (a) `FileListController` に作業セット操作 `addFiles` / `removeFile` / `clearFiles`(本仕様 REQ-004〜006 準拠)を追加。(b) 時系列ソートのラベルを「作成日時」→「**更新日時**」に変更(REQ-003。`createdAt` を実データで保証できないため)。(c) 各行に**場所(フォルダ)をサブ情報として表示**(REQ-009)= `RowView` に場所を含め、行 UI の副題に出す。→ 002 spec.md の該当 REQ を更新 → 再承認。
- **001-rename-core(Strict)**: (a) `FileEntry` に**元場所ハンドル**(識別・書き戻し用の不透明値。REQ-002)を追加。(b) `FileEntry` に**表示用の場所情報**(元フォルダの人間可読文字列。REQ-009)を追加。(c) 日時トークンの「作成(created)」基準の表記/扱い(撮影日時は後続機能で導入するため、004 段階では「更新」を中心に)。→ Strict のため 001 の契約更新 → `spec_lint --strict` → 人間の再承認。ハンドル/場所の置き場(`FileEntry` フィールド / data 層ラッパ)は実装判断(004 T2)。

## 自由とする点（実装に委ねる）

- `FileSource` の具体実装(SAF / OS ピッカー / 使用プラグイン)とキャンセル/エラー検出の方法。契約(REQ-001/002/008)を満たせば自由。`Cancelled` と `Failed` を実装がどう見分けるか(ピッカーの戻り値・例外の捕捉等)は自由。
- 元場所ハンドルの文字列形式(URI 文字列 / パス)・表示用の場所文字列の形(フルパス / フォルダ名)と、`FileEntry` フィールドか data 層ラッパかの持たせ方(REQ-002/009 を満たせば自由)。
- エラー通知の UI 表現(SnackBar / ダイアログ等)。REQ-008 の「作業セット無変化のままユーザーに理由が伝わる」を満たせば自由。
- 作業セットの内部データ構造・重複排除の実装(順序保持と REQ-004〜006 を満たせば自由)。
- 単一 `pickFolder`/`pickFiles` 呼び出しが返す**リスト内の並び順**は未定義(プラットフォーム依存)。作業セットは**追加された順**を保持し、初期ソートは `custom`(追加順)。以後の並び替え/ソートは 002 の責務。
- `Failed` の理由分類(`permissionDenied`/`io`/`unknown`)の内部判定基準は実装に委ねる(REQ-008 は「理由を通知する」までを規定)。

## 対象外・未定義とする点

- **隠し/システムファイルのフィルタリングはしない**(決定 D-2)。004 は実装が返したものをそのまま扱い、不要ファイルはユーザーが 002 の個別選択解除で外す。理由: 隠し/システムの判別にクロスプラットフォームで確実な手段が無い(Android SAF は先頭ドット名の慣習のみで明示フラグ無し、Windows は隠し/システム属性があるが Dart から読むにはネイティブ実装が要り、かつ先頭ドット慣習ではない)。将来「隠しを隠す」トグルは確実な判別手段の導入を前提に後続で検討。
- `Failed` の理由の**粒度を超えた詳細**(スタックトレース提示・リトライ導線)。REQ-008 は理由の通知までを規定し、リトライ等は後続。
- 同時/並行の選択操作(単一ユーザー・単一プロセス前提)。
- 実ファイルの書き込み・リネーム(005)。撮影日時・横断ギャラリー(後続機能)。

## 決定済み事項（旧 open_questions・2026-08-04 開発者回答で確定）

- **D-1(旧 OQ-1)キャンセルとエラーの区別**: 区別する。`Cancelled`=閉じて未選択(無変化・通知なし)、`Failed`=決定後のアクセス失敗(無変化・**理由をユーザーに通知**)。この通知は 005 の命名警告(命名結果の検証)とは性質が異なる読み込み時アクセス失敗の通知で、別チャネルとする(REQ-001/008)。
- **D-2(旧 OQ-2)隠し/システムファイル**: フィルタしない(実装が返したものをそのまま扱い、不要は 002 で選択解除)。クロスプラットフォームで確実な判別手段が無いため(対象外節参照)。将来トグルは判別手段の導入を前提に後続。
- **D-3(旧 OQ-3)返り順**: 追加順。作業セットは追加順を保持し、002 の初期ソートは `custom`(=追加順)。以後はソートで並び替え(REQ-007)。
- **D-4(旧 OQ-4)場所の表示**: 同名か否かに関わらず、各行に**場所(フォルダ)をサブ情報として常時表示**(作成/更新日時と同格の副題)。要件化(REQ-009)。
