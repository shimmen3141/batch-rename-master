# ファイル読み込み(file-source) 振る舞い仕様

- Status: draft <!-- T7(読み込み導線の再設計)のため再承認待ち。approved 化は人間 -->
- Level: Light（正しさの正本は本ファイル）

## 目的（説明的・正誤判定には使わない）

実ファイルの読み込み入口を定義する。利用者はまず**リネームしたいファイルの種類**を選び、種類に応じた選択 UI で**フォルダを辿ってファイルを複数選択**し、確定した集合がそのままリネーム対象のリストになる。抽象ポート `FileSource` がこの選択結果を `FileEntry` 群で返し、各ファイルは**元場所ハンドル(URI/パス)**で一意に識別される(005 のリネーム書き戻し先)。**選択は 1 回で完結し、蓄積しない**(2026-08-05 の決定。旧「作業セット(かご)方式」は取り消し)。純粋部分(ポート契約・置き換え・002 への結線)はサンドボックスで検証し、実 SAF/実ピッカーはホスト検証。

## 境界

- 対象（in scope）: **種類の選択**(どの選択 UI へ進むか)、`FileSource` ポートの契約(`pickFiles` と結果型 `PickResult`=`Picked`/`Cancelled`/`Failed`)、`FileEntry` の**元場所ハンドル**と**表示用の場所**、確定した選択集合で 002 のリストを**置き換える**結線、`Failed` 時のエラー通知。
- 対象外（out of scope）: リネーム実行=実ファイル書き込み(005)。命名エンジン(001)・リスト/選択/ソート/プレビュー(002)・ルール構築(003)の既存振る舞い。**画像の撮影日時(不変キー)と「すべて/アルバム」横断ギャラリー**(MediaStore/EXIF ベース)は後続の専用機能。サブフォルダ再帰探索。ストレージ/権限の具体実装(SAF・OS ピッカー・使用プラグイン)は `FileSource` 契約を満たす限り自由(実装は T4。**新導線の実装は T9**)。
- アクター: ユーザー(種類の選択・ファイルの選択)、`FileSource` 実装(プラットフォーム)、`FileListController`(リネーム対象リストの保持)。
- 入力: ユーザーの選択操作 → `FileSource` が返す `PickResult`(`Picked(entries)` / `Cancelled` / `Failed(error)`)。
- 出力: 002 のリストに反映されたファイル群(表示順・選択状態・場所サブ情報・プレビュー)、`Failed` 時のユーザー通知。
- 永続化される状態: なし(セッション内のリストのみ。権限 URI の永続保持は実装内の詳細)。
- 外部副作用: 読み取りのみ(フォルダ列挙・メタデータ取得・権限取得)。書き込みなし。

## 振る舞い

### 操作（`FileSource` ポート契約）

結果は3値の直和 `PickResult` で表す(不正な状態を型で排除する):

- `Picked(entries)`: 選択が確定した。`entries` は 0 件以上(空フォルダは空の `Picked`)。各 `FileEntry` は元場所ハンドルを持つ。
- `Cancelled`: ユーザーがピッカーを閉じ、何も選ばなかった(決定していない)。
- `Failed(error)`: 選択後のアクセス・列挙に失敗した。`error` は理由(`permissionDenied` / `io` / `unknown`)+任意メッセージ。

| 操作 | 契約 |
|------|------|
| `pickFiles()` | ユーザーに**フォルダを辿ってファイルを複数選択**させ、確定した集合を返す。結果を `Picked` / `Cancelled` / `Failed` のいずれかで返す。例外を投げない(REQ-001/008)。 |

`pickFolder()`(フォルダ単位のツリー権限で全件を読み込む経路)は**契約に含めない**(OQ-1 が解消し、システム画面の「Select all」で一括選択できることを実機で確認したため)。実装コードの削除は T9 で行う。

### 操作（002 コントローラ側）

| 操作 | 契約 |
|------|------|
| `setFiles(entries)` | 現在のリストと選択を**捨てて** `entries` で置き換える。全件が既定で選択状態(REQ-004/005)。**蓄積しない**(旧 `addFiles` のハンドル重複排除・末尾追加は取り消し)。 |
| `removeFile(handle)` | `handle` に一致するファイルをリストと選択から除去する。一致が無ければ無変化(REQ-006)。 |
| `clearFiles()` | リストと選択を空にする(REQ-006)。 |

### 要件

| ID | 優先度 | 要件（外部から観測可能な文で） | 検証 |
|---|---|---|---|
| REQ-001 | must | `pickFiles()` は結果を `Picked(entries)` / `Cancelled` / `Failed(error)` のいずれかで返す(例外を投げない)。選択確定=`Picked`(空フォルダは空の `Picked`)、閉じて未選択=`Cancelled`、権限拒否・IO 失敗=`Failed`。 | VER-001 |
| REQ-002 | must | 各 `FileEntry` は安定した**不透明な元場所ハンドル**(SAF URI / ファイルパス相当の文字列)に対応づく。2つのエントリはハンドルが等しいとき同一ファイルとみなす(005 の書き戻し先の特定と、`removeFile` の一致判定の基準)。 | VER-001, VER-002 |
| REQ-003 | must | 各 `FileEntry` は `name`・`modifiedAt`・`size` を持つ。**作成日時は取得できたときだけ設定し、取得できなければ「不明」として返す**(`modifiedAt` 等で代替して埋めない)。SAF には作成日時の列が無いため、取得は他の経路(REQ-010)に依存する。 | VER-001 |
| REQ-004 | must | `setFiles(entries)`: 現在のリストと選択を捨てて `entries` で**置き換える**。**蓄積しない**(前回の選択は残らない)。空リストで置き換えた場合はリストが空になる。`entries` に**同一ハンドルが複数含まれていた場合は1件にまとめる**(ハンドルは同一ファイルの識別子であるため。REQ-002)。 | VER-002, VER-003 |
| REQ-005 | must | `setFiles` で置き換えた全エントリが既定で選択状態になる。 | VER-002, VER-003 |
| REQ-006 | must | `removeFile(handle)` は一致エントリをリストと選択から除去し、`clearFiles()` は両方を空にする。一致が無ければ無変化。 | VER-002 |
| REQ-007 | must | 結線: `pickFiles()` が `Picked` を返したら `setFiles` でリストを置き換え、002 のリスト(件数・表示順)とプレビューがその集合になる。表示順は**選択結果の順**で、初期ソートは `custom`。以後の並びは 002 のソートに委ねる。 | VER-003 |
| REQ-008 | must | 結線の結果別挙動: `Cancelled` は**リスト無変化**(前回の選択が保たれる)・通知なし。`Failed(error)` はリスト無変化のまま**ユーザーにエラー(理由)を通知する**。この通知は 005 の命名警告(重複・桁不足=命名結果の検証)とは別チャネルの、読み込み時アクセス失敗の通知である。 | VER-003 |
| REQ-009 | should | 各 `FileEntry` は**表示用の場所情報**(元のフォルダ)を持ち、002 の各行に**サブ情報**として表示される(作成/更新日時・サイズと同格の副題。同名ファイルの見分けにも役立つが、同名に限らず常に表示)。表示用の場所は人間可読の文字列で、識別用の不透明ハンドル(REQ-002)とは別物でよい。 | VER-003 |
| REQ-010 | should | 作成日時の取得は単一手段に限定せず、**取得できた経路の値を用い、どの経路でも取得できなければ「不明」とする**。経路の優先順位は ① コンテンツ由来の撮影/作成日時(EXIF `DateTimeOriginal`・動画コンテナ・PDF・Office・XMP)→ ② プラットフォーム由来の作成時刻(Android MediaStore `DATE_TAKEN`/`DATE_ADDED`、Windows NTFS `CreationTime`)。**推測値・代替値を作成日時として返さない**(REQ-003)。どの経路を実装するかは自由(下記)。 | VER-001 |
| REQ-011 | must | 読み込みは**種類の選択から始まる**。種類は **「画像」「動画」「文書」「すべて」の4つ**(2026-08-05 決定)。「**すべて**」と「**文書**」はシステムのファイル選択画面を開く(文書は文書系の MIME で絞り込む)。(一括選択はシステム画面の「Select all」で成立することを実機確認済み。ツリー権限へは戻さない。)「**画像**」「**動画**」は**枠のみ**を用意し、選んでも読み込みは行わず「未実装(写真機能で対応)」を示す(ギャラリー/MediaStore は権限モデルが別。境界参照)。 | VER-003 |
| REQ-012 | should | 確定した選択に**複数の親フォルダのファイルが混ざっている**場合、その旨をユーザーに警告する(読み込み自体は行う)。理由: 001 の重複検証は最終名集合を全ファイル横断で数えるため、別フォルダの2件が同名になっても**実際には衝突しないのに重複警告**が出る。この安全弁は 004 側に置き、001 の判定範囲は変更しない。 | VER-003 |

### 代表例

| # | 入力/操作 | 期待 |
|---|---|---|
| 1 | 種類「すべて」を選ぶ → fake `pickFiles()` が [a,b] を返す | リスト=[a,b]、両方選択 |
| 2 | 続けて `pickFiles()` が [c,d] を返す | リスト=**[c,d]**(前回の [a,b] は残らない。**蓄積しない**) |
| 3 | `pickFiles()` が `Cancelled` | リスト不変(前回の選択が保たれる)・通知なし |
| 4 | `removeFile(cのハンドル)` | リスト=[d]、選択から c も除去 |
| 5 | `clearFiles()` | リスト=[]、選択=空 |
| 6 | 同名だが別ハンドルの2件を1回の選択で受け取る | 2件とも別ファイルとしてリストに載る(ハンドルで識別) |
| 6b | **同一ハンドル**の2件が1回の選択に含まれる | **1件にまとめられる**(ハンドルは同一ファイルの識別子。REQ-004) |
| 7 | 空の `Picked`(1件も選ばず確定) | リストが空になる(REQ-004) |
| 8 | `pickFiles()` が `Failed(permissionDenied)` | リスト無変化・**ユーザーにエラー通知**(005 の命名警告とは別チャネル) |
| 9 | 場所付きの a を読み込む → 002 の行を見る | a の行に場所(フォルダ)がサブ情報として表示される |
| 10 | EXIF 撮影日時を持つ写真を読み込む | その `FileEntry` の作成日時が撮影日時になる(REQ-010) |
| 11 | EXIF を持たないスクリーンショットを、どの経路でも取得できない環境で読み込む | 作成日時は**不明**。`modifiedAt` で埋めない(REQ-003) |
| 12 | 上の 2 件を読み込んだ状態で作成日時ソート | 撮影日時のある行はその値、不明な行は**更新日時で代替**して並ぶ。002 が「取得できない 1 件を更新日時で代替」と警告(002 REQ-002/011)。004 が返す作成日時は不明のまま(REQ-003) |
| 13 | 種類「画像」または「動画」を選ぶ | 読み込みは行わず「未実装(写真機能で対応)」が示される(REQ-011) |
| 14 | 種類「文書」を選ぶ | 文書系の MIME で絞り込んだファイル選択画面が開く(REQ-011) |
| 15 | 親フォルダが2つに跨る選択を確定する | 読み込みは行われ、**跨っている旨の警告**が出る(REQ-012) |
| 16 | 親フォルダが1つだけの選択を確定する | 警告は出ない(REQ-012) |

## 自由とする点（実装に委ねる）

- `FileSource` の具体実装(SAF / OS ピッカー / 使用プラグイン)とキャンセル/エラー検出の方法。契約(REQ-001/002/008)を満たせば自由。`Cancelled` と `Failed` を実装がどう見分けるか(ピッカーの戻り値・例外の捕捉等)は自由。
- 元場所ハンドルの文字列形式(URI 文字列 / パス)・表示用の場所文字列の形(フルパス / フォルダ名)と、`FileEntry` フィールドか data 層ラッパかの持たせ方(REQ-002/009 を満たせば自由)。
- エラー通知の UI 表現(SnackBar / ダイアログ等)。REQ-008 の「リスト無変化のままユーザーに理由が伝わる」を満たせば自由。REQ-012(親フォルダ跨ぎ)の警告の見せ方も同様に自由。
- リスト置き換えの内部実装(順序保持と REQ-004〜006 を満たせば自由)。
- `pickFiles()` が返す**リスト内の並び順**は未定義(プラットフォーム依存)。002 は受け取った順を保持し、初期ソートは `custom`。以後の並び替え/ソートは 002 の責務。
- `Failed` の理由分類(`permissionDenied`/`io`/`unknown`)の内部判定基準は実装に委ねる(REQ-008 は「理由を通知する」までを規定)。
- **種類選択・選択 UI の見た目**(タブ・カード・ボトムシート等)。REQ-011 の「種類を選ぶと対応する選択 UI が開く」を満たせば自由。
- **作成日時の取得経路を、どこまで実装するか**(REQ-010 の①②のうち何を実装するか、プラグイン/FFI/自前パーサのいずれを使うか)。取得できなければ「不明」とする契約(REQ-003)を満たす限り自由で、**経路を後から追加しても本仕様は変わらない**(不明の件数が減るだけ)。

## 対象外・未定義とする点

- **隠し/システムファイルのフィルタリングはしない**(決定 D-2)。004 は実装が返したものをそのまま扱い、不要ファイルはユーザーが 002 の個別選択解除で外す。理由: 隠し/システムの判別にクロスプラットフォームで確実な手段が無い(Android SAF は先頭ドット名の慣習のみで明示フラグ無し、Windows は隠し/システム属性があるが Dart から読むにはネイティブ実装が要り、かつ先頭ドット慣習ではない)。将来「隠しを隠す」トグルは確実な判別手段の導入を前提に後続で検討。
- `Failed` の理由の**粒度を超えた詳細**(スタックトレース提示・リトライ導線)。REQ-008 は理由の通知までを規定し、リトライ等は後続。
- 同時/並行の選択操作(単一ユーザー・単一プロセス前提)。
- 実ファイルの書き込み・リネーム(005)。撮影日時・横断ギャラリー(後続機能)。

## T5 由来の更新（2026-08-04・開発者再承認済み）

開発者決定「作成日時ソートを残す」に伴い、作成日時の扱いを更新した。実装は T6。

- **REQ-003 を更新**: 作成日時は**取得できたときだけ設定し、できなければ「不明」**とする（`modifiedAt` 等で代替して埋めない）。旧文「004 の時系列の基準は `modifiedAt` であり作成日時としては提示しない」は取り消し。
- **REQ-010 を追加**: 取得は**優先順位付きチェーン**（① コンテンツ由来: EXIF `DateTimeOriginal`・動画コンテナ・PDF・Office・XMP → ② プラットフォーム由来: MediaStore `DATE_TAKEN`/`DATE_ADDED`、Windows NTFS `CreationTime`）。どの経路を実装するかは自由で、**追加しても仕様は変わらない**（不明の件数が減るだけ）。
  - 補足（非規範）: SAF には作成日時の列が無い。`stat()` の `ctime` は inode 変更時刻であり作成時刻ではない。Windows の `CreationTime` は本物の作成時刻だが**コピーで更新される**ため撮影時刻とは限らない。
- 波及（実装前に人間の再承認が必要。T5 で更新済み）:
  - **001（Strict）**: `FileEntry` の作成日時が「不明」を取りうる／基準日時が取得不能なら日時トークンは空文字列（REQ-004）／`validate` が基準日時不明を警告（REQ-014）／不明を別の日時で代替しない（INV-006）。
  - **002（Light）**: 時系列ソートを**作成日時・更新日時の2種**に（REQ-002。**不明な item は更新日時をソートキーに代替**）／作成日時ソート時に**不明の件数と代替した旨を警告**（REQ-011）／不明を含んでも失敗しない（REQ-012）／各行が**両日時と不明フラグ**を供給（REQ-013）。
  - 代替は 002 の**並べ替えキーと表示に閉じる**。004 が返す作成日時は不明のまま（REQ-003）で、001 の命名でも代替しない（001 INV-006）。名前は後から直せないため、命名と並べ替えでリスクが異なる。
