# T29 選択モードの見せ方とケバブメニューを整える

## 目的

`T28` で入れた除去のための選択モード(002 REQ-018)について、実機確認で受領した要望
**7件**(下の5件 + 「追加で受領した2件」)を実装する。
**`T28` の欠陥ではない** — 承認済みの REQ-016 / REQ-017 / REQ-018 と代表例 6e〜6j はすべて
実機で成立している(`T28` の「manual確認の結果(2026-09-19)」)。002 spec は文言・配色・レイアウトを
非規範としているので、ここで変えるのはその範囲である。

## 受領した要望(2026-09-19、原文)

> - 長押しするとチェックマークが左側に現れるが、これによって画像の位置などの表示がかくつく。右端のドラッグ用のつまみの位置に現れるようにすれば、かくつきが発生しないのでそうしたほうが良いと思う。
> - 選択されたファイル行は、わかりやすいように色を変えたほうが良いと思う。私が使っているファイルアプリでは、背景が#41384Dになり、チェックマークは#D0BFEAの円に#41384Dのチェックマークという色でした（選択時）。チェックボックスも円になっていました。
> - 選択されているファイルが0件になったら自動的に選択モードが解除されるほうが直感的です。
> - 選択モード中において、「外すファイルを選ぶ 2件」のような表示は冗長で分かりにくいです。「2件選択中」のように簡潔にしてください。「リネーム構成から外す」も、押せることがわかりにくいのでアイコン一つにしてください(一覧を空にするで使っているものと同じでよい)。アイコンは右寄せで表示してください。
> - ケバブメニューを設けたいです。上記で述べたアイコンの右隣にケバブメニューを配置し、押すと「すべて選択」「すべてをリネーム対象から外す」の二つを表示し、「一覧を空にする」ボタンの機能はこちらが引き継ぐ形です。

補足(同日): 「**ケバブメニューは未選択モード・選択モードの両方で同じ位置に表示するイメージです。**」

### 追加で受領した2件(2026-09-19、原文)

> - 未選択モード時の「外すファイルを選ぶ」もケバブメニューの中に入れたほうが良さそうです。
> - 選択モード中は、画面下部の帯(リネームルールボタンやリネーム実行ボタンがある部分全体)を非表示にしたほうが混乱が少なそうです。また、「別フォルダへ」ボタンも同様に非表示にしたほうが良いと思いました。

**どちらも承認済みの要求と衝突しない。**

- 「外すファイルを選ぶ」をケバブへ入れても **REQ-018 の入口(b) は満たす** — (b) が課すのは
  「一覧が空でない間は常に到達でき、**マウスと支援技術から操作できる**」ことで、ケバブの項目は
  どちらも満たす(1 tap 増えるだけである)。**長押しに依存しない入口が消えるわけではない。**
- 下部の帯と `別フォルダへ` をモード中だけ隠すのは**提示の選択**である。005 は
  「**場所・文言・UI部品は自由とする点に残したまま**」と明記しており(revision 9.0)、
  REQ-019 が課すのは「実行が始まらない・実ファイルを1件も変えない」という**振る舞い**である。
  004 も読み込み導線の常時表示を課していない(REQ-011 / REQ-015 は読み込みの**手順**の要求)。
  **005 REQ-020 の「命名ルールが未設定」の案内は下部の帯ではなく一覧側の帯なので、隠れない。**

## 変更範囲

1. **checkbox を行の右端へ**(つまみと同じ位置)。左に出すと preview と名前が横へずれて**かくつく**。
   モード中はつまみを出さない(REQ-018)ので位置は競合しない。**`T02` が 002 REQ-014 を廃止して
   つまみが常時出るようになっても、この置き方は成立する**(モード中はつまみを隠すため)。
2. **選択された行の配色**。参考値は背景 `#41384D`、チェックは `#D0BFEA` の円に `#41384D` のチェック、
   checkbox は**円**。**色は `AppColors` のセマンティック名で参照する**(UI側の規約)ので、
   必要なら token を足す。既存の dark theme と並べて見比べ、浮くなら明度を寄せる。
3. **選択が0件になったらモードを自動で解除**する。
   **ただし「入った直後の0件」では解除しない** — ヘッダの入口(REQ-018 (b))は0件で始まるので、
   即座に抜けると入口が機能しなくなる。**1件以上選ばれた後に0件へ戻ったとき**に抜ける。
4. **ヘッダの簡潔化**。「外すファイルを選ぶ」+ 件数 → **「2件選択中」**。
   「リネーム候補から外す」→ **アイコン1つ**(`一覧を空にする` と同じもの)で**右寄せ**。
   押せることが分かるよう tooltip と無効時の表現を残す。
5. **ケバブメニュー**を**両モードで同じ位置**(ヘッダ右端、外すアイコンの右隣)へ置く。
   中身は「すべて選択」「すべてをリネーム対象から外す」。**`一覧を空にする` の機能はここが引き継ぐ**。
6. **通常表示の `外すファイルを選ぶ` もケバブの中へ**入れる(ヘッダから独立したbuttonを消す)。
7. **モード中は下部の帯(ルール設定と実行)と `別フォルダへ` を隠す。** モードは外す作業に
   専念させる。**一覧側の「命名ルールが未設定」の案内(005 REQ-020)は隠さない** — 下部の帯ではなく
   一覧の帯なので、そもそも別物である。

## 決めること(実装前に確定する)

- **通常表示のケバブの中身**。「すべて選択」は通常表示では**モードへ入って全件を選んだ状態**にするのが
  自然(そうでないと通常表示に選択の概念が生まれ、002 REQ-016 と衝突する)。
  「すべてをリネーム対象から外す」は `clearFiles`(004 REQ-006)で、**取り消せる**(REQ-017)。
- **`file_source_bar.dart` の `一覧を空にする`(`clear-files-button`)を撤去するか**。要望は
  「機能はこちらが引き継ぐ」なので撤去するが、**002 と 004 の決定節に
  「読み込み帯の『すべて外す』を『一覧を空にする』へ改名した」という記録がある**
  (`008:T03` 由来の更新)。`T27` と同じ形で**取り消し線で差し替え、移設先を書く**。
  REQ の改訂は要らない(004 REQ-006 は状態層、002 REQ-016 は場所を定めていない)。
- **`T27` の決定節の文言の助言と逆になる点**を追記する。決定節は「`〇件選択中` だけでは
  『選んだものを rename する』と読まれうる」として外すことを名指しする見出しを勧めていた。
  **要望4 はそれを開発者が上書きしたものである**。REQ-018 は文言を縛っていないので再承認は不要だが、
  **記録が矛盾したままにはしない**。誤読を防ぐのは、外すアイコンの tooltip とケバブの文言が引き受ける。

## 実装(2026-09-19)

### 決めたこと

- **選択モードの状態を [`RemovalSelection`](../../../../lib/ui/file_list/removal_selection.dart)
  (`ChangeNotifier`)へ出した。** `T28` では `FileListView` の `State` に置いていたが、
  **モード中は一覧の外側**(読み込み帯の `別フォルダへ`)**も隠れる**ので、一覧の外の widget も
  同じ状態を読む必要がある。composition root(`main.dart`)が1つ作り、帯と一覧へ配る。
  **`FileListController` とは別のままである**(rename 対象の選択と混ぜない)。
- **配色はアプリのアクセント(シアン)で作った**(2026-09-19 の開発者の判断)。構造は要望どおり
  (面を染める → 塗りつぶしの円 → 暗いチェック)で、**指定色(背景 `#41384D` / 円 `#D0BFEA`)は
  `AppColors` の2 token を差し替えるだけで試せる**。
- **0件で抜けるのは「利用者が選択を外して0件になったとき」だけ**である。入口(ケバブ)は0件で
  始まるので、そこで抜けるとREQ-018 (b)の入口が機能しなくなる(対照は M330)。
- **ケバブは一覧が空のときだけ出さない。** どの項目も対象が無いためである。
- **checkbox とつまみは同じ 32px の枠に入れ、モード中に出す側を行が1か所で決める。**
  親側にも `!selecting` を持たせると二重の判定になり、**片方を壊してもtestが気付かない**
  (mutation M309 が最初 SURVIVED した)。

### 参考designから離れた点

`docs/design/Bulk Renamer.html` は行に常時 checkbox、ヘッダに `n / m 件を選択`、
下部バーに実行を持つ。**選択モードもケバブも描かれていない。** 002 REQ-016 / REQ-018
(`T03`・`T27` 承認)と 2026-09-19 の決定に従い、離れる。
