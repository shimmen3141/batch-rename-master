# T30 選択モードで帯の高さを保ち、外すアイコンに補足を添える

## 目的

除去のための選択モード(002 REQ-018)へ**出入りするときに読み込み帯の高さが変わらない**ようにし、
**外すアイコンが何をするのかを初見で読める**ようにする。

## 受領した要望(2026-09-19、原文)

`008:T29` の実機確認で受領した5件のうちの2件である。

> - 選択モードに切り替わる際、「別フォルダへ」ボタンが消えるためか、ヘッダーの高さが変わって表示ががたつく。
> - 選択モード中に表示される、リストから外すためのボタンのアイコンが初見ではわかりにくい。「別フォルダへ」ボタンが消えてアイコンの上にスペースができるので、そこにアイコンに対して吹き出しで説明・補足を表示するとよいかも。文言は「押すとリネームリストから外されます。ファイルは削除されません。」のような感じで、吹き出しのツノがアイコンから出るイメージ。

## この2件を同じtaskへ置く理由

**互いを解くからである。** 帯の高さが変わるのは `別フォルダへ`(`OutlinedButton`、縦padding 8 + 枠)が
消えて、場所のラベル(12px)だけが残るためで、**空いた枠を吹き出しが埋めれば高さも保たれる**。
別々に実装すると「枠を空のまま確保する」→「そこへ吹き出しを入れ直す」と二度作ることになる。

**ただし高さの保持を吹き出しの有無に依存させない。** 吹き出しを将来消したり、一度見たら
出さない形にしたりしても、**帯の高さは変わってはならない** — 枠そのものを確保して、
吹き出しはその中身として置く。

## 変更範囲

- [`lib/ui/file_source/file_source_bar.dart`](../../../../lib/ui/file_source/file_source_bar.dart)
  — `別フォルダへ`(`pick-files-button`)を隠している分岐が高さを落としている箇所。
- 吹き出しの描画(新しい widget になる見込み)。ツノ付きの箱は `CustomPainter` か
  `Stack` + 三角で作る。**アイコンの位置から出ている**ことが分かる形にする。
- 対象のアイコンは一覧ヘッダ側の `removalModeRemoveKey`(`removal-mode-remove`)である。
  **帯と一覧は別の widget なので、ツノをアイコンへ正確に向けるには位置の受け渡しが要る**
  (下の「先に決めること」)。

## 先に決めること

- **ツノをどう合わせるか。** 帯(`FileSourceBar`)と外すアイコン(`FileListView` のヘッダ)は
  別の木にある。案は3つ:
  1. **右端に合わせるだけ**にする(アイコンは右寄せなので、吹き出しの右端を同じ余白に揃えれば
     ツノの位置は固定値で足りる)。**いちばん安く、壊れにくい。**
  2. `GlobalKey` + `RenderBox` でアイコンの中心を測り、ツノをそこへ置く。正確だが、
     文字倍率・狭幅・再builtのたびに測り直す必要があり、**測る前の1 frameで位置がずれる**。
  3. 吹き出しを一覧ヘッダ側(アイコンと同じ木)へ置き、帯は**高さの確保だけ**を行う。
     ツノは正確に出せるが、**帯の空き枠は空のまま**になり要望の「空いたスペースを使う」から離れる。

  **推奨は 1。** アイコンは右寄せで固定されており(`008:T29` の要望4)、折り返しも起きない。
- **吹き出しを出し続けるか、一度で消すか。** 要望は「初見では分かりにくい」なので、
  **モードに入るたびに出す**のが素直である(状態を持たない)。`007` の保存領域へ
  「もう見た」を書くのは**保存schemaを増やす**ので、必要と判断したときだけにする。
- **文言。** 受領した原文は「押すとリネームリストから外されます。ファイルは削除されません。」
  **後半(実ファイルは消えない)は落とさない** — 005/013 が守っている境界そのもので、
  `T03` が「外す」の取り違えを避けるために改名した経緯とも同じ系統である。
- **狭幅・大きい文字での折り返し。** 2行に収まらないときに帯が伸びると、今度はそこで
  高さが変わる。**モードの出入りで高さが変わらない**ことを保証するのは、
  「通常表示の高さ ≥ モード中の高さ」ではなく**同じ高さ**である。

## 実装(2026-09-19)

### 決めたこと

- **枠の残し方は `IndexedStack` である。** `if (!selecting)` で button を外すと、
  枠(縦 padding 8 + 枠線を持つ `OutlinedButton`)が丸ごと消えて帯が場所のラベルの高さまで縮み、
  **下の一覧が跳ねる**。`IndexedStack` は**出していない側も layout する**ので、
  高さも幅も両方の max で固定される。
  **`Visibility(maintainSize:)` ではなくこちらにした理由**は、吹き出しを
  「もう一方の状態」として同じ枠に入れられるからである(枠を空で確保してから
  別の場所に吹き出しを作る、という二度手間が要らない)。
- **`find.byKey` の見え方は変わらない。** `IndexedStack` の出していない側は
  描画・hit test・semantics のいずれからも辿れないので、既定の finder から見つからない。
  **`T29` の「モード中は `別フォルダへ` を出さない」test はそのままの形で通る**
  (`skipOffstage: false` にして初めて見える)。M332 は `if (!selecting)` から
  `index` へ再アンカーした。
- **ツノの合わせ方は「右端合わせ」ではなく「共有した数」にした。** 当初の推奨は
  右端合わせだったが、**外すアイコンは右端ではない**(右端はケバブである)。
  [`header_metrics.dart`](../../../../lib/ui/file_list/header_metrics.dart) に
  ヘッダの padding・アイコンの枠・ケバブの枠を置き、帯とヘッダの両方がそれを使う。
  **合っているかは widget test が実測する**(ツノの中心 == アイコンの中心)ので、
  数が実体とずれたら落ちる(対照は M354)。
- **吹き出しは常にモード中に出す**(状態を持たない)。「一度見たら出さない」は
  `007` の保存schemaを増やすので採らなかった。
- **`GlobalKey` でアイコンを実測しない**(案2)。測る前の1 frameで位置がずれ、
  文字倍率や再buildのたびに測り直すことになる。

### 参考にした原文から離れた点

**文言を「押すとリネームリストから外されます。」から「押すと一覧から外れます。」へ縮めた。**
3行になると吹き出しが `別フォルダへ` の枠(40)より高くなり、**通常表示の帯まで太る** —
高さを揃えるために吹き出しは通常表示でも layout されるので、高いほうが帯の高さを決める。
実測で 1回この状態を作ってしまい(帯が 64 → 75 へ)、字を 10px・幅を 156・2行へ収めて戻した。
**「ファイルは削除されません。」は落としていない**(005 / 013 の境界そのもの)。
何の一覧かはヘッダの `〇件選択中` とアイコンの tooltip が示す。
**この置き換えが妥当かは実機で見てもらう。**

### 残したコスト

**通常表示でも帯の末尾の枠が `別フォルダへ`(320dpで約133)から吹き出しの幅(156)へ広がり、
場所の取り分が約23px 減る。** 吹き出しを layout しないと高さを揃えられないためである。
320dp では場所の幅が約155 → 約132になる(先頭省略・末尾優先は `008:T23` のまま)。
**帯の高さは変わっていない**(65のまま)。
