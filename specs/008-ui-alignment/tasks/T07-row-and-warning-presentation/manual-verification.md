# 手動確認: 008:T07 行と警告の情報階層

## 何を確かめてほしいか

自動testで閉じられなかったものだけを残してあります。**5項目、20〜30分**です。

| # | 確かめること | なぜ機械で閉じられないか |
|---|---|---|
| 1 | 画像のpreviewが行に出る。件数の多いfolderでも待たされず、アプリが重くならない | 速度とメモリは実機でしか測れない(残余risk **N-5**) |
| 2 | **動画**のpreviewが行に出る。**縦横比が保たれている** | Kotlinの`MediaMetadataRetriever`はCIで動かせない(**N-5**)。`getScaledFrameAtTime`が比を保つかは実機依存(**N-6**) |
| 3 | 狭幅で `作成日時: 不明` が最後まで読める | `004:T10`で見切れを観測した条件そのもの。widget testは通っているが、実機のfontで再確認する |
| 4 | **文字サイズを最大**にしても、どの行が「不明」か分かる | 端末のfont設定を機械側で再現していない(**N-7**) |
| 5 | 警告帯を開いたとき、内訳が以前より多く読める | 「読めるか」は人の目で見る。件数の閾値を機械で決めない |

**preview が出ない行があること自体は不具合ではありません。** 種別アイコンに落ちるのが設計上の
正常な結果です。**壊れた絵や、行の高さのガタつき**があれば不具合です。

## 手順1 — 画像のpreviewと、件数の多いfolder

1. 「**ファイルを選ぶ**」を押す。
2. 種類のシートで「**すべて**」を選ぶ(Androidでは「画像」「動画」はまだ写真機能待ちで、
   選ぶと案内のsnackbarが出ます)。
3. app内のfile browserが開く。ショートカットの「**DCIM**」を押し、`Camera`へ入る。
4. **20件以上をcheckして**「**確定**」を押す。少ない端末では`Download`や`Pictures`も足して
   ください。

**見るところ**

- [ ] 各行の左に**写真の縮小画像**が出る。
- [ ] preview が出るまでの間、行が**アイコンのまま**で、高さや文字の位置が**動かない**
      (絵が入った瞬間に行がガタつかない)。
- [ ] **一覧を上下に速くscrollする。** 引っかかり・数秒の固まりが無い。
- [ ] `broken-fixture.jpg` の行が、**画像アイコンでも写真でもない別のアイコン**(壊れた画像の
      印)になっている。

> ここで見ているのが残余risk **N-5** の前半です。**「重い」と感じたら、その体感をそのまま
> 教えてください。** 秒数を測る必要はありません。

## 手順2 — 動画のpreview(**N-5 / N-6**)

1. 手順1と同じ経路で、今度は**動画を含むfolder**(`DCIM/Camera` または `Movies`)から
   **動画を3件以上**選んで確定する。
2. 動画が無ければ、端末のカメラで5秒ほど録画してから同じ操作をしてください。

**見るところ**

- [ ] 動画の行に**その動画の一場面**が出る(黒一色ではない)。
- [ ] **縦横比が崩れていない。** 横長の動画が縦に潰れて見えたり、人や物が細長く/平たく
      なっていない。**枠は正方形で、はみ出す分は切り取られるのが正しい**見え方です。
- [ ] 動画のpreview が出ない場合も、**壊れた絵ではなくフィルムのアイコン**に落ちている。

> ここが **N-6** です。**「歪んでいるかもしれない」と迷ったら、その行のスクリーンショットを
> ください。** 正方形へ切り取っているので歪みが見えにくく、迷うのが普通です。

## 手順3 — 狭幅で `作成日時: 不明` が読めるか

**端末を縦向きにしてください。**(`004:T10`で見切れを観測したのはこの向きです。)

1. 一覧の上のソートで「**作成日時順**」を選ぶ。

**見るところ**

- [ ] 各行の下に「**作成日時: 不明**」が出て、**末尾の「不明」まで欠けずに読める**。
      Androidでは作成日時を取得できないため、**全行が「不明」になるのが正しい**動作です。
- [ ] 「不明」の左に**警告の印**が付き、色が他の文字と違う。
- [ ] 「場所」(`Camera` など)が**日時とは別の行**に出ている。
- [ ] 幅が足りないときに**削られるのは「更新日時」の側**である(「作成日時」が優先して残る)。

## 手順4 — 文字サイズ最大(**N-7**)

1. 端末の 設定 > ディスプレイ > **フォントサイズ**(または「表示サイズとテキスト」)を
   **最大**にする。
2. appへ戻る(再起動は不要です)。

**見るところ**

- [ ] どの行が「不明」なのかが**警告の印で分かる**。
- [ ] 行が**赤い縞模様(overflow)**になっていない。
- [ ] 文字が枠の外へはみ出していない。

> **「作成日時: 不明」の文字が途中で `…` になるのは、この設定では想定内**です(印は消えない
> ので、どの行かは分かります)。**印まで消えている / 行が崩れている**場合だけ不具合です。
>
> 一覧の**上のヘッダ**が崩れることがありますが、**それはこのtaskの範囲外**で `008:T10` が
> 引き受けます(残余risk **N-8**)。見つけたら教えてください。直すのは別taskです。

確認したら、フォントサイズを**元に戻して**ください。

## 手順5 — 警告帯

1. 一覧の下の「**変更する名前を設定する**」を押す。
2. 「**＋ 自由テキスト**」を押し、`photo` と入力して確定する。**トークンはこれ1つだけ**に
   します(全fileが同じ名前になり、重複警告が件数ぶん出ます)。
3. シートを閉じ、一覧の上に出る「**警告 N 件(…)**」を押して開く。

**見るところ**

- [ ] 内訳が**scrollできる**。
- [ ] **一度に3件以上**読める(以前は2件しか入りませんでした)。
- [ ] 警告の領域が**画面の半分を超えて**一覧を覆っていない。
