# T60 リネーム画面の行の補足情報に出す日時を、並び順とルールが使う日時だけにする(002 REQ-013 の更新)

## 目的

リネーム画面の行の補足情報を減らし、名前を読みやすくする。**行 UI が提示する日時を、並び順またはルールが使っている日時だけ**にする仕様(002 REQ-013)を定める。実装は `T61`。

## 出所

- `T59` の補足情報の帯(案A)を 2026-10-07 のエミュレータ確認で開発者が採らなかった(「補足情報を枠に収めてみるアプローチでは、あまりわかりやすくなりませんでした。枠は消し、別のアプローチを考えます。補足情報自体の情報量を減らす(ソートやリネームのチップによって表示するものを変える)ことや、変更前後の名前の方を強調するなどが考えられそうです。」)。
- Agent が3案(A: 使う日時だけ出す / B: 名前を強める / C: 両方)を示し、開発者は **A** を選んだ。あわせて「「作成日時:」「更新日時:」から日時を省いて「作成:」「更新:」でよい」「一致しているなら「作成・更新:」のように書けばよい」と挙げ、「ルールで作成・更新の両方を使っていない場合」を尋ねた。
- Agent の案 ①見出しなしで更新日時 / ②見出し付き / ③出さない のうち、**開発者は ① を選び、仕様を承認した**(原文: 「①(見出しなしで更新日時)でよいです。仕様は承認します。」)。

## 決めたこと

002 `spec.md` の REQ-013・代表例 14〜15・14b〜14d、「008 T60 由来の更新」節。要点:

- 日時を**使っている** = `sortMode` がその日時、またはルールがその日時を基準にする日時トークンを持つ(現在日時は数えない)。
- 使っている日時だけを、どの日時かが分かる形で出す。両方で表示上同じなら1つにまとめてよい。どちらも使っていなければ更新日時を、どの日時かを示さずに出す。
- 作成日時が不明であることは、作成日時を出しているときだけ示す。強調の条件(`sortMode` が作成日時)と 005 REQ-009 との境界は変えない。
- **行データの供給は変えない**(REQ-013 の前半、REQ-011)。

**この変更で無くなる保証**: 以前の代表例 14 は「名前順でも作成日時が不明であることを(強調せずに)表示する」だった。これを取りやめる。並び順でもルールでも作成日時を使っていなければ、作成日時が不明でも名前の結果にも並びにも影響しないため(開発者が承認)。
