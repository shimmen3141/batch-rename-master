# T15 警告を行に出す提示を定義する

## 目的

警告を**一覧上部の集約帯**から**各行**へ移す。どのファイルが何を理由に警告されているかを、
行を見れば分かるようにする。**002 と 005 の仕様更新であり、人間の再承認が要る。**

`T16`が実装する。**承認前に実装を始めない**(`plan.md`の方針)。

## なぜ必要か

`T07`が`360dp`で計測した。重複警告30件を開くと**1件が4行へ折り返して68px**になり、
当時の固定132pxの内訳には**2件しか入らなかった**。folderを跨ぐ重複は通常経路で出る
(008の(i))ので、件数が多いのは例外ではない。

原因は情報の置き場所である。現在の文面は

```text
重複: 「{file名}」({場所})の変更後名「{変更後名}」が他のファイルと重複します
```

で、**file名・場所・変更後名だけが行ごとに違い、残りは全行で同一**である。同じ説明が
件数ぶん繰り返され、その繰り返しが幅を食っている。

`T07`は帯の高さを画面に応じるようにしたが(2件→3件相当)、**置き場所を変えないと解けない**
と判断して人間へ返した。開発者は「警告は各ファイルと一緒にあった方が、どのファイルが
何の原因で警告されているか分かりやすい」と決定した(2026-08-27)。

## 参考designが同じ形を持っている

`docs/design/Bulk Renamer.html`の行データにこれがある。

```js
warn: bad,
warnText: r.dup ? '⚠ 他のファイルと同じ名前になります' : '⚠ 連番の桁数が足りません',
rowBg: bad ? 'rgba(248,113,113,.06)' : 'transparent',
cardBorder: bad ? '1px solid rgba(248,113,113,.35)' : ...
```

ヘッダには `warnLabel: warnCount ? '⚠ ' + warnCount + ' 件の問題' : '問題なし'`、詳細は
種別ごとの見出しと説明を持つdialog(`'名前の重複 N 件'` + `desc: '末尾に (1) (2) … を
自動付与して回避します。'`)である。

**参考designに集約帯は無い。** 現在の`RenameWarningPanel`は005が独自に作ったものである。

**designから採らないもの**: dialogの`dlgConfirmLabel: '自動解決して実行'`と
「自動解決して続行できます」。これは**振る舞い**であり、005(強制実行)や`013:T11`(再採番)
とは別物である。**提示だけを揃え、判定と実行は持ち込まない。** designは配置・導線・
情報階層の土台であって正本ではない(AGENTS.md)。

## 決めること

### 1. 行が何を持つか(002)

現在`RowView`は現在名・変更後名・選択状態しか持たず、警告は`FileListController.warnings`
という**一覧全体のflat list**である。行へ出すには行データが警告を持つ必要がある。

- 行が持つのは**種別だけ**か、種別 + 短い一文か。
- 開発者の想定は「簡潔な形で1〜2行に列挙」(例: ファイル名重複・ファイル名が空・
  連番の桁不足・作成日時不明)。**すべて併発しても2行に収まること**を要求に落とすか。
- 002 REQ-010/REQ-013 が既に供給している場所・日時と、どう並ぶか。

### 2. 集約帯をどうするか(005)

- 帯を**廃止**して、ヘッダの件数(`⚠ N 件の問題` / `問題なし`)へ置き換えるか。
- 005 REQ-009 が求める「そのファイルとそのトークンが特定できる」を、**行 + 詳細**で
  満たす形へ書き換える。REQ-010(0件なら出さない)も置き換え先で定義し直す。
- 詳細は**トグルかmodalか**。modalなら`T14`と重なるので分担を決める(`T14`は実行前確認
  dialogを持つ)。
- **帯の高さの決め方を引き継ぐか。** `T07`が上限を**画面**の割合にした結果、開いた帯が
  **一覧の見える範囲の半分以上**を覆うことがある(`T07`の残余risk N-9、2026-08-29に実機で
  観測)。帯を廃止するなら消える論点だが、**残す形を選ぶなら上限の基準を一覧の取り分へ
  変える**必要がある。

### 2-b. 作成日時の代替warningは行へ移さない(開発者の入力)

**`_CreatedAtFallbackBanner`(002 REQ-011)は`RenameWarningPanel`とは別のwidget**で、いま既に
header付近に出ている。開発者は2026-08-29の`T07`実機確認で「**作成日時不明時に更新日時で
代替する警告だけは、警告が無いと挙動が分からないので、現在のようにheader付近でよい**」と
述べた。

これは**行へ移す対象から外す**という意味である。行の「作成日時: 不明」が示すのは
*そのfileの値が無い*ことで、banner が示すのは*一覧全体の並び順が別のkeyで決まっている*
ことである。**粒度が違う**ので、この判断は行への集約と矛盾しない。決定として書き残すこと。

### 3. まとめ規則を1つ足すか(005 REQ-021)

開発者の案: **ファイル名が空なら、そのファイルの重複警告は行に出さない**(詳細では出す)。

REQ-021 は現在**ちょうど1つ**のまとめ(空名 + 基準日時不明を1行に)を定めている。ここへ
2つ目を足す変更である。**判定は001のままで、提示だけを変える**ことを明記する。

### 4. 検証をどう置き換えるか

現在の`VER-005`は、**行ごとに説明文が繰り返されていること**を要求の証拠にしている。

- `warning_display_test.dart:172` — 帯の`Text`の数が`警告件数 + 1`
- 同`:180` — `作成日時が不明`が**2件ぶん**見つかる
- `empty_rule_test.dart:169` — 1行の`Text.data`が`名前が空になります`と`基準日時が取れない`の両方を含む

**緩めるのではなく、付け替える。** REQ-009 が要求するのは対象fileが識別できることなので、
行 + 詳細でそれを検査する形へ書き直す。`T16`の受け入れ証拠に、置き換え後のtestが
**元の要求を同じ強さで**押さえていることを入れる。
