# T26 読み込み画面の状態復元を定義する

## 目的

「ファイルを選ぶ」を開き直したときに、**前回の場所を開き、前回選んだファイルを選択済みにする**かを
決め、004 spec へ書いて人間の承認を得る。実装は承認後に別taskへ切り出す。

## なぜ位置づけが変わったか

`008:T03` が**行の checkbox を廃止**し、「一覧にあるファイル＝ rename 対象」にした
(002 REQ-016)。その結果、

- **外す**のは行の × で1手、
- **戻す**のは…直後なら取り消せる(002 REQ-017)が、**それを過ぎるとフォルダごと選び直す**
  (004 は置き換え方式。REQ-004)。

という非対称が生まれた。**この候補は便利機能ではなく、その非対称を埋める導線**である。

## 決めること

- **復元するのは何か。** 前回の場所(folder)だけか、選んだファイルの選択状態も含むか。
- **004 REQ-004(蓄積しない)と両立させる形。** 復元は「前回の選択を**残す**」ではなく
  **「選び直しの初期値」**である必要がある — 確定するまで一覧は変わらず、確定したら
  **置き換える**。ここを曖昧にすると蓄積方式へ逆戻りする。
- **いつまで覚えているか。** app が生きている間だけか、`007` の永続化に載せて次回起動でも残すか。
- **前回の場所が無くなっていたら**どうするか(権限が変わった、SDカードが抜かれた、folderが消えた)。
- **どこに出すか。** 復元した状態で開くのか、「前回の場所から選ぶ」という選択肢を出すのか。
  後者なら 004 REQ-015 の browser の入口(`008:T11` が定義する)に並ぶ。
- **desktop でも成立するか。** OS の picker は状態を持てないので、Android だけの要求になる可能性がある
  (その場合は spec に platform 差として書く)。
