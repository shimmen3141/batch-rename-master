# T26 読み込み画面の状態復元を定義する

## 目的

「ファイルを選ぶ」を開き直したときに、**前回の場所を開き、前回選んだファイルを選択済みにする**かを
決め、004 spec へ書いて人間の承認を得る。実装は承認後に別taskへ切り出す。

## なぜ位置づけが変わったか

`008:T03` が**行の checkbox を廃止**し、「一覧にあるファイル＝ rename 対象」にした
(002 REQ-016)。その結果、

- **外す**のは行の × で1手、
- **戻す**のは…直後なら取り消せる(002 REQ-017)が、**それを過ぎるとフォルダごと選び直す**
  (004 は置き換え方式。REQ-004)。

という非対称が生まれた。**この候補は便利機能ではなく、その非対称を埋める導線**である。

## 決めること

- **復元するのは何か。** 前回の場所(folder)だけか、選んだファイルの選択状態も含むか。
- **004 REQ-004(蓄積しない)と両立させる形。** 復元は「前回の選択を**残す**」ではなく
  **「選び直しの初期値」**である必要がある — 確定するまで一覧は変わらず、確定したら
  **置き換える**。ここを曖昧にすると蓄積方式へ逆戻りする。
- **いつまで覚えているか。** app が生きている間だけか、`007` の永続化に載せて次回起動でも残すか。
- **前回の場所が無くなっていたら**どうするか(権限が変わった、SDカードが抜かれた、folderが消えた)。
- **どこに出すか。** 復元した状態で開くのか、「前回の場所から選ぶ」という選択肢を出すのか。
  後者なら 004 REQ-015 の browser の入口(`008:T11` が定義する)に並ぶ。
- **desktop でも成立するか。** OS の picker は状態を持てないので、Android だけの要求になる可能性がある
  (その場合は spec に platform 差として書く)。

## 着手時に受領した方針(2026-10-03、原文)

> T26に着手してください。ただ、既存の「別フォルダへ」に状態復元を導入するかは考える余地があると考えています。最初から選びなおす導線は残しつつ、同じフォルダからそのまま追加できる導線も新たに作るのが良いと思っています。どのような導線・配置・UIにするかよい案があれば教えてください。私が考えていたのは、T24の案と組み合わせて、ファイル行の一覧の先頭にフォルダ用の行を設け、そこから同じフォルダの選択画面を開く導線を作ることでした。

- `別フォルダへ`(最初から選び直す)は残す。復元をそこへ入れるかは未定。
- **同じ folder から追加する導線を新設する**方向。置き場所の候補は一覧先頭の folder 行(`T24` の案)。

### 開発者の決定(2026-10-03): 追加は案A

> 追加については案Aを取ります。

- **案A**: 同じ folder の browser を、**一覧にあるファイルを選択済みにした状態**で開く。確定したら今どおり**置き換える**
  (004 REQ-004 の「蓄積しない」は変えない。「選択の初期値」を足す)。チェックを足せば増え、外せば減る。
- 退けた案B: 一覧にあるファイルを選べなくし、確定で末尾へ足す(REQ-004 を置き換えと追加の2本立てにする)。
- 復元する状態は**一覧から導く**(folder = 一覧の所属 folder、選択 = 一覧のハンドル)。別に覚えない。

### 開発者の決定(2026-10-03): 入口は一覧先頭の folder 行(案1)

> 案1で進めてください。

- 一覧の先頭に細い folder 行(folder 名と右端の `＋ 追加`)を置き、スクロールしても先頭に残す。上部の帯は変えない。
  帯との名前の重複が気になるかは実機で見てから判断する。
- 行全体のタップでは開かない(`T24` の折りたたみのために空ける)。選択モード中と、場所を持たない一覧(demo data)では出さない。
- 退けた案: 2(帯から folder 名を消す。`T08` の決定を変える)、3(帯に `＋ 追加` を足す)。
