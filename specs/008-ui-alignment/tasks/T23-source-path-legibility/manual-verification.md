# 手動確認: 読み込んだ場所の表示

## 何を確かめてほしいか

`008 / T23` で、**場所が幅に入りきらないときは先頭を省略して末尾を残す**ようにしました
(2026-09-18 にご指摘いただいた `Internal shared st...` の件。案Aです)。
あわせて、**起動直後のデモデータを2つのフォルダに分けました**(質問2)。複数フォルダの
表示は製品の操作からは到達できないので、ここだけが実機で見られる経路です。

自動testが押さえているもの(幅ごとにどの候補を選ぶか、`/` を含まない文言を変えないこと、
はみ出さないこと、帯とbuttonの位置)は**手順に入れていません**。お願いするのは
**実機の字形で読めるか**だけです。

| | |
|---|---|
| 対象 | **`008 / T23` 読み込んだ場所の表示を読めるようにする** |
| **`lib/` の最終commit** | 依頼時にお伝えします |
| branch | `asdd/008-ui-alignment/T23-source-path-legibility` |
| 端末 | **Android実機** |

**branchの切り替えは不要です。** Agent が `/workspace` をこのbranchにしたまま待ちます。

[`docs/development/emulator-verification.md`](../../../../docs/development/emulator-verification.md)
にあります。

## 手順1 — 起動直後(1分)

読み込みは**しないで**ください。デモデータのまま見ます。

- **確認A**: 帯の場所が **`複数のフォルダ`** になっている(フォルダ名は出ない)。
- **確認B**: 各行に**場所が出ている**。上の3行は `…/DCIM/Camera` 系、`scan document.pdf` や
  `memo.txt` は `…/Download` 系です(幅が足りれば
  `Internal shared storage/DCIM/Camera` のように丸ごと出ます)。
- **確認C**: 行の場所が**どのフォルダのものか読み分けられる**。`Internal shared st...` のように
  共通部分だけが残っていない。
- **確認D**: 行が窮屈になっていない(場所は日時とは別の行に出ます)。

## 手順2 — 読み込んだあと(2分)

[`008 / T07` のfixture](../T07-row-and-warning-presentation/manual-verification.md)
(`DCIM/t07-fixtures`。27件)を読み込みます。`ファイルを選ぶ` → `すべて` →
`DCIM/t07-fixtures` で27件を選んでください。

- **確認E**: 帯の場所が **`…/t07-fixtures`**(または `…/DCIM/t07-fixtures`、
  幅が足りれば `Internal shared storage/DCIM/t07-fixtures`)になっている。
  **`t07-fixtures` が読める**のが要点です。
- **確認F**: `…` の位置と形が**読んで分かる**。「先頭が省略されている」と伝わるか、
  別の記号のほうがよいかも教えてください。
- **確認G**: 27行のどこにも場所が出ていない(1フォルダなので行には出ません)。
- **確認H**: 帯が画面幅いっぱいで、`別フォルダへ` の位置が動かず、はみ出しの赤い縞が無い
  (`T08` で固定した保証が生きているか)。

## 手順3 — 文字を大きくしたとき(1分)

端末の設定で文字サイズを**最大**にして、手順2の画面をもう一度見ます。

- **確認I**: 場所が**さらに短く**なるが、**末尾の `t07-fixtures` は残る**
  (入りきらなければ `t07-fix…` のように末尾が削れます。これは想定どおりです)。
- **確認J**: はみ出しの赤い縞が出ない。
