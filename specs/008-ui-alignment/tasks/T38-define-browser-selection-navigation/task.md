# T38 app内browserの選択・戻る導線を定義する

## 目的

2026-09-22のT37エミュレータ確認報告で、範囲選択は概ね動く一方、全選択後の一括解除、画面を閉じる×の意味、選択行の表示、保存場所とfolderの戻り方が直感的でないと指摘された。004の承認済みの振る舞いを守りつつ、Android app内browserの操作導線を一つの設計へ整理し、必要な仕様変更を開発者の承認へかける。実装はT39が持つ。

## 入力と既存taskとの境界

- 観測: 2026-09-22のT37エミュレータ確認報告（会話）。「概ね機能」「TalkBack手順の意味が不明」「全選択はあるが全解除は無い」「headerの×が選択解除の×に見える」「checkboxをリネーム画面へ統一したい」。
- 開発者の案: footer左下に暗い背景・シアンの枠と文字の「リネーム画面に戻る」button、上部を保存場所名と左矢印にし、選択中は×と「〇件選択中」へ変える、現在地の帯へfolder一括選択checkboxを置く。
- 004 REQ-015/016/020: **保存場所が複数なら一覧から、1つだけならその保存場所のrootから始めること**、**複数あるときは閉じずに切り替えられること**、rootより上へ辿れないこと、folder移動で選択が消えること、全選択は現在folder直下のfileだけを対象にすることを保持する(**2026-09-22の`T11`で入口が変わり、近道は取りやめた**)。変更したい場合は仕様案を作り、承認前に実装しない。
- T11/T12: 保存場所1件時の入口、**近道の撤去**、戻る矢印の向き、空folder表示を持つ。T38はT11の承認済みの意味を前提に定義し、それらを複製しない。T39はT12の実装結果とも整合させる。
- T37: 長押しdragとedge自動scrollの意味を変えない。T38は選択controlと画面を閉じる操作の提示を持つ。
- desktopのOS pickerは対象外。

## 決めること

1. 一括解除をどこに置き、全選択と一対の操作として見せるか。候補は現在地帯の一括checkbox、headerの×、ケバブ。複数の同義操作を無造作に並べない。
2. headerの×を撤去してfooterへ「リネーム画面に戻る」を常時表示するか。閉じたときは現在と同じく未確定の選択を捨て、rename画面の既存状態を保持する。
3. 保存場所名を上部へ、現在folderの場所をその下へ置くか。左矢印はfolder内なら親folderへ、保存場所rootなら保存場所一覧へ戻るのかを区別し、rootより上のfilesystemへは移動しない。
4. 選択時に上部を「× + N件選択中」に変える場合、×は「現在folderの選択を全部解除」か「選択表示を閉じる」かを明確にし、画面を閉じる操作と誤認させない。
5. 「folder全体checkbox」は直下fileだけを選ぶのか、子folder以下も含むのか。REQ-020は前者を要求し、後者はfolder移動と同一folder選択の保証を変えるため、明示承認なしに採らない。
6. file行のcheckboxをメイン一覧T29の右端・円形・アクセント色に揃え、選択済み行の面色も揃えるか。browser固有のfolder行はnavigationとして識別できる形を保つ(**近道は2026-09-22の`T11`で取りやめた**)。
7. TalkBackを知らない開発者でも、manualのUI説明だけで全選択と一括解除の操作を再現できるか。

## 2026-09-23 の決定と操作状態表

### 開発者の決定

| 論点 | 決定 |
|---|---|
| `×` の意味 | **選択中だけ出し、「現在folderの選択をすべて解除」だけを意味する。** 画面は閉じない |
| 画面を閉じる導線 | **footer左下の「リネーム画面に戻る」に一本化**する。未確定の選択は捨て、rename画面の既存状態は保つ |
| 選択0件のheader | 同じ位置に **`←`(上へ)とルート(保存場所)の名前**だけを出す |
| 選択中のheader | 同じ位置が **`×` + 「N件選択中」** へ変わる。**`←`は消える**(上へ戻るには先に解除する) |
| 現在地の帯 | 戻るboutonを消し、**パンくず**にする(`内部ストレージ › Pictures › Screenshots`) |
| パンくずのtap移動 | **別taskへ分ける**(このtaskでは表示だけ)。選択中に上へ移動する手段は、それが入るまで無い |
| 「すべて選択」 | footerから外し、**headerの右端に固定したケバブ**へ入れる。**選択の有無にかかわらず常設**で、件数にも関わらず出し続けてよい |
| 「選択をすべて解除」 | **1件でも選択されているときだけ**ケバブへ出す |
| file行のcheckbox | メイン一覧(`T29`)へ揃える(右端・円・アクセント色)。選択済み行の面色も揃える |
| folder一括checkbox | **置かない**(「すべて選択」がケバブへ移ったため、現在地帯にcheckboxを持たせない) |

**`×`とケバブの「選択をすべて解除」は同義だが、意図して両方置く。** `×`は速い経路、ケバブは**操作名で認識できる経路**である
(004 REQ-020が全選択へ同じ理由で求めているもの)。**無造作な重複ではない**ことをここに記録する。

### 操作状態表

`←`と`×`は**同じ位置**を共有する。ケバブは**常に右端**にあり、位置が動かない。

| 現在地 | 選択 | header 左 | header 中央 | header 右 | 現在地の帯 | footer |
|---|---|---|---|---|---|---|
| 保存場所の一覧 | — | 無し | 「ファイルを選ぶ」 | ケバブ(「すべて選択」は**無効**) | 無し | 「リネーム画面に戻る」 / 「確定」(**無効**) |
| root(保存場所が複数) | 0件 | `←`(**保存場所の一覧へ**) | 保存場所名 | ケバブ | パンくず(保存場所名のみ) | 「リネーム画面に戻る」 / 「確定」(無効) |
| root(保存場所が1件) | 0件 | **無し**(それより上へは辿れない) | 保存場所名 | ケバブ | 同上 | 同上 |
| 下位folder | 0件 | `←`(**親folderへ**) | 保存場所名 | ケバブ | `保存場所名 › A › B` | 同上 |
| 下位folder | 一部 | `×`(**全解除**) | 「N件選択中」 | ケバブ(「すべて選択」+「選択をすべて解除」) | 同上 | 「リネーム画面に戻る」 / 「確定」(**有効**) |
| 下位folder | 全件 | `×` | 「N件選択中」 | 同上(「すべて選択」は**無効**) | 同上 | 同上 |
| 空のfolder | 0件 | `←` | 保存場所名 | ケバブ(「すべて選択」は**無効**) | 同上 | 「リネーム画面に戻る」 / 「確定」(無効) |

- **folderを移動すると選択は解除される**(004 REQ-016)。したがって移動後のheaderは必ず`←`側の形に戻る。
- **「すべて選択」の対象は現在folder直下のfileだけ**(004 REQ-020)。folderと、選べないentryは含めない。
- **「選択をすべて解除」の対象も現在folderの選択だけ**である(選択は同一folder内に限るため、それ以外に選択は存在しない)。
- **Androidのシステムバックは「リネーム画面に戻る」と同じ**(未確定の選択を捨てて閉じる)。
