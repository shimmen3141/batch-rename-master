# 手動確認: 行のファイルの大きさ(Androidエミュレータ・Windows desktop)

**対象buildは、`lib/`・`hook/`・`src/`の内容が commit `5b93d9f` と同一のもの**である(1回目)。branch `asdd/008-ui-alignment/T48-row-file-size` のHEADからbuildすればこれを満たす。**code・dependency・build設定が変わったら、この結果は再利用しない。**

大きさの書き方(単位・丸め)と、狭い幅・文字倍率ではみ出さないことは自動testで確かめてある。ここで見るのは**実機の字体での並び方と読みやすさ**である。test の字体(1文字 = 1文字ぶんの幅)は実際より広く、スマホ幅では大きさが3行目に落ちる。**実際の字体では「更新日時」の横に収まる見込み**で、それを確かめる。

## 使う端末と準備

- 起動と`flutter run`は`/workspace/docs/development/emulator-verification.md`のとおり。**host側でworktree `.worktrees/008-T48-row-file-size` へ`cd`してから`flutter pub get` → `flutter run`**する(branchの移動は不要)。
- ファイルは選ばなくてよい。起動直後のデモの一覧を使う。リネームは実行しない。

## 0. いま動いているのが、このbuildか確かめる

起動直後、一覧の各行の小さい灰色の文字(作成日時・更新日時)の後ろに、`2.3 MB` のような大きさが出ていれば、このbuildである。

## 1. 行の大きさ

デモの一覧で、たとえば次のように出る(単位は 1024 刻み。デモの値は 2,400,000 バイトなので `2.3 MB`)。

| ファイル | 出る大きさ |
|---|---|
| `IMG_0009.jpg` | `2.3 MB` |
| `scan document.pdf` | `527 KB` |
| `memo.txt` | `1 KB` |
| `archive.tar.gz` | `9.4 MB` |

**こうなってほしい**

- 大きさが**ラベル無し**で、日時と同じ小さい灰色の文字で出る。目立ちすぎない。
- スマホの幅では、大きさが**「更新日時」と同じ行の右側**に収まり、行が以前より高くなっていない(もし大きさだけが次の行へ落ちて行が高くなっていたら、それを伝えてほしい)。

## 2. 文字サイズ最大

端末の設定で**文字サイズを最大**にしてアプリへ戻る。

**こうなってほしい**

- はみ出す所や、大きさの文字が欠ける所が無い(大きさが次の行へ落ちるのは構わない)。

確認後、文字サイズを元へ戻す。

## 3. Windows desktop

hostで同じworktreeから`flutter run -d windows`し、広い窓と狭い窓で一覧を見る。

**こうなってほしい**

- 広い窓では、作成日時・更新日時・大きさが1行に並ぶ。
- 狭い窓でも、はみ出す所や文字が欠ける所が無い。
