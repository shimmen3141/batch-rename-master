# 手動確認: 警告の詳細

## 何を確かめてほしいか

`008 / T19`(警告の詳細modalを作り直す)で、詳細を**原因ごとの節**へ組み直し、
**行から開いたらその行だけ**が出るようにしました。

自動testが既に押さえているもの(スコープが混ざらないこと、説明が該当件数ぶん
繰り返されないこと、行と詳細の語彙が同じこと、場所の括弧が同名のときだけ出ること)は
**手順に入れていません**。ここでお願いするのは、**件数が多いときに実機で読めるか**だけです。

| | |
|---|---|
| 対象 | **`008 / T19` 警告の詳細modalを作り直す** |
| **`lib/` の最終commit** | 依頼時にお伝えします |
| branch | `asdd/008-ui-alignment/T19-warning-detail-modal` |
| 端末 | **Android実機**(狭幅) |

**branchの切り替えは不要です。** Agent が確認用のworkspaceを用意して、確認が終わるまで動かしません。
共通の起動手順は
[`docs/development/emulator-verification.md`](../../../../docs/development/emulator-verification.md)
にあります。

## 事前準備

[`008 / T07` のfixture](../T07-row-and-warning-presentation/manual-verification.md)(`DCIM/t07-fixtures`。27件)を
読み込み、**全選択**にします。ルールを次のようにします。

- **自由テキスト `photo`** と **作成日時(YYYYMMDD)** の2つ。

fixtureの画像は作成日時を持たないので日時トークンは空になり、**同じ拡張子のファイルが同じ名前**に
なります。fixtureは `.png` が24件・`.jpg` / `.txt` / `.pdf` が1件ずつなので、**`.png` の24件が
`photo.png` で重複**し、残る3件は重複しません(重複は拡張子を含めた変更後名で判定します)。

- 「名前の重複」**24件**
- 「作成日時不明」**27件**(全件)
- 合わせて **51件**

`task.md` の受け入れ証拠が求める「重複が数十件」の状態です。

## 手順1 — 件数から開く詳細が長すぎない(3分)

1. 一覧の上の **`⚠ 51 件の問題`** を押します(件数が違っても、下の確認には影響しません)。

- **確認A**: 詳細が開き、**節ごとに「説明が1つ + 対象の列挙」**になっている。
  「変更後の名前が他のファイルと同じになります」のような説明が27回繰り返されていない。
- **確認B**: **縦に長すぎない。** 節の見出しと説明が、scrollしなくても意味を取れる位置にある。
  (以前は同じ文が件数ぶん並び、何の話か分からなくなっていました。)
- **確認C**: ファイル名に**場所の括弧が付いていない**(同名のファイルが無い状態なので)。

## 手順2 — 行から開く詳細(2分)

1. 詳細を閉じ、**どれか1行の警告**(行の右の赤いバッジ)を押します。

- **確認A**: **その行のファイルだけ**が出る。ほかの26件が出てこない。
- **確認B**: 見出しに**そのファイル名**が出ている。
- **確認C**: 指で**押しやすい**。狙いを外して別のものが反応する、ということがない。

## 手順3 — 語彙が揃っている(1分)

- **確認A**: 行のバッジと詳細の見出しが**同じ言葉**になっている
  (`名前が重複` と `名前の重複`、`作成日時不明`)。`基準日時なし` や `桁不足` という言い方は出てこない。

2. ルールを **連番(1桁・開始1)** だけに変えます(10件目以降が2桁になります)。

- **確認B**: 行のバッジも詳細の見出しも **`連番の桁不足`** になっている。

## 結果の返し方

会話で自由に書いてください。**「問題なかった」だけでも構いません**が、**どの確認まで見たか**を
書いていただけると、Agentが記録を過大にしません。気になった点は**そのままの言葉**で書いてください。

## 結果を受け取ったあとのAgent作業

1. 結果と対象commitを`task.md`へ記録します(開発者の言葉は原文のまま引用します)。
2. 不成立があれば直し、`lib/`が動いた場合は**動いた範囲だけ**の再確認をお願いします。
3. 成立していれば、PRをreadyにしてmergeします。
