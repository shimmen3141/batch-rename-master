# T19 警告の詳細modalを作り直す

## 目的

`T17`で承認された仕様どおり、警告の詳細を**行スコープと全件スコープ**に分け、同じ説明が
ファイルごとに繰り返される形をやめる。

## 入力と依存

- **`T17`で承認された 002 / 005 spec。承認前に着手しない**(`plan.md`の方針)。
- 現行実装: `lib/ui/file_list/rename_warning_view.dart`(`describeWarning`、詳細dialog、
  `presentWarnings`)。
- `T18`が決める「行のどこを押すと開くか」。**入れ物はこのtaskが持つ。**

観測の出所は[`T16`のtask.md](../T16-implement-row-level-warnings/task.md)の
「受領したUIの改善要望(2026-09-02、原文)」。番号は同節のもの。

  全件。`T17`が承認した形に従う。
- **要望3(重複)**: 「『ルールの問題』と『桁不足1件』の2セクションで重複して桁不足に
  触れられている」。要望7で桁不足が行の警告になるため、セクションの持ち方ごと組み直す。

### 詳細modalの作り直し方

- **節を「原因ごと」に組み直す**(要望3・4)。改修前は「ルールの問題」(原因の説明)と種別ごとの
  ファイル列挙が別の節にあり、桁不足が両方へ出て重複していた。**節ごとに「説明1つ + 対象の列挙」**にする。
- **説明は節の先頭に1つだけ**置く(REQ-009 (2))。単位は原因(トークン)ごとで、日時トークンが2本なら節が2つになる。
- **場所の括弧は既定で出さない**(要望4)。ただし**同じ表示名が2件以上並ぶときだけ**添える —
  REQ-009 は「どのファイルが対象かを識別できる形」を課しており、同名が並ぶと名前だけでは識別できない。
- **スコープを分ける**(要望2、REQ-009 (4))。行から開いたらその行のファイルの警告だけ、ヘッダの件数から
  開いたら全件。どちらにも他方が混ざらない。

### REQ-021 のまとめは行だけに効かせる

空名と基準日時不明が同時に該当するファイルは、**行では結果へ畳む**(規則1)。**詳細では両方を残す** —
REQ-009 (3)/(4) が「(1) では読めない情報(トークンの名指し)へ到達できること」を課しているので、原因の節を
落とすと名指しへ到達できない。ファイルは「名前が空」の節と原因の節の両方に並ぶが、**説明は原因ごとに1つ**なので
REQ-009 (2) に反しない。

### 件数の数え方(`008:T16` から引き受けた R-A の決着)

**`⚠ N 件の問題` の N は提示単位の数とする** — 001 の警告のうち REQ-021 規則1 で畳んだぶんを1件に数え、
それ以外は 001 が返した件数のまま。開発者が確認を求めた「82件」(27件 × 日時トークン3本 + 桁不足1)がこの数え方である。
**ファイル数に変えない** — `T18` / `T20` の実機確認がこの表示のまま成立しており、変えると証拠を取り直すことになる。
数え方を固定する assertion をこのtaskで置く(R-A が「無い」と指摘したもの)。

### machine検証する範囲

- スコープの両方向(行から開くと他のファイルが混ざらない / ヘッダから開くと全件が出る)。
- 同じ説明が**該当30件でも1つ**であること。**節ごとの説明が1つであること。**
- 種別の文言が行と詳細で**同じ語彙**であること(`作成日時不明` / `更新日時不明` / `連番の桁不足`)。
  **基準を取り違えないこと**(作成日時トークンで「更新日時不明」と出ない)。
- 場所の括弧が**既定で出ず、同名が並ぶときだけ出る**こと。
- **出ない方向**(`T18` から引き受け): 導線の無い `FileListView` 単体では原因の説明を出さない。
- **行の警告のtap範囲が縮む方向**(`T18` の穴C): `padding` を 0 にすると落ちる assertion を置く(`M227`)。
- 件数の数え方(上の R-A)。

### machineで閉じられない範囲と引き受け先

- **詳細が縦に長すぎないか**(要望4の主観的な部分)。該当が数十件の状態でAndroid実機のmanual確認で見る。
- 余白・字体・階層は **`008:T10`**。modalの形(bottom sheet / 中央dialog)は **`008:T14`**
  (`T06` の実機確認で開発者が問いを出した)。
