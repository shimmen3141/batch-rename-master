# T27 まとめて外す導線(長押しの選択モード)を定義する

## 目的

行の **×** と**ドラッグ用のつまみ**が隣り合っていて押し間違えうる問題を、
**長押しで選択モードへ入り、まとめて外す**形で解けるかを決め、002 spec へ書いて承認を得る。
実装は承認後に別taskへ切り出す。

## 受領した提案(2026-09-18、原文)

> なお、少し思ったこととして、ドラッグ用のつまみと×ボタンは並べないほうがよさそうです。×ボタンをカードの右上に移動させることも考えましたが、小さくなって押しにくいのと、複数のファイルを外すときに一つずつ押す必要があって面倒そうです。そこで、長押しすると選択・編集モードに切り替わって、複数選択・リネーム候補から外す操作ができるようになるのはどうでしょうか（一般的な画像ファイルアプリなどにもよくある仕様）。長押しするとヘッダー部分が×(選択モードを解除)、〇件選択中、リネーム候補から外すボタンの3つに切り替わるイメージです。これによって、ドラッグつまみと×ボタンの押し間違いを根本的になくせると思いました。

観測の出所は [`T04`](../T04-implement-selection-flow/task.md) の
「manual確認の結果(2026-09-18。2回目)」。**`T04` の欠陥ではない** — ×とつまみが隣り合うこと自体は
承認済みの振る舞い(002 REQ-003 の並び替えと REQ-009 の除去)に反していない。

## 先に解く仕様の衝突

**002 REQ-016 は「行 UI は選択の切り替えを提示しない」と定めている**(2026-09-18 に `T03` で
開発者が再承認したばかり)。長押しの選択モードは、

- **rename 対象の選択ではない**(対象は一覧にあるファイル全部のまま)。選ぶのは「これから外すもの」で、
  モードを抜ければ選択は消える。
- しかし**利用者から見れば行にcheckboxが出る**。REQ-016 の文面とは衝突する。

したがって、**REQ-016 の範囲を「常時の選択」に限定する改訂**か、**除去のための一時的な選択を
別の要求として足す**かのどちらかが要る。**Agentが勝手に緩めない** — 改訂案を作って承認を得る。

## 決めること

- **REQ-016 をどう書き直すか。** 「常時は提示しない」「除去のための一時的な選択は別」と読める形にする。
  代表例 6e(行に checkbox が無い)も書き換わる。
- **モードの入り方と抜け方。** 長押しで入る。抜けるのはヘッダの ×、システムの戻る、外し終えたとき。
  **並び替え(ドラッグ)はモード中どうなるか**(つまみを隠すのか、そのまま使えるのか)。
- **ヘッダの3つ**(× / `〇件選択中` / `リネーム候補から外す`)の文言。`T03` で「選択」という言葉を
  UI から消したので、**`〇件選択中` が「rename 対象の選択」と読まれないか**を確かめる。
- **取り消し**(002 REQ-017)との関係。まとめて外した分は**1回の取り消しで全部戻る**のが素直である。
- **通常モードの × を残すか。** 残すなら押し間違いの問題は残る。無くすなら1件外すのに長押しが要る。
  **つまみと × を離す**(例: × を行の左端へ、つまみだけ右端)という第三の案もある。
- **desktop と accessibility での代替。** 長押しはマウスに無い。右クリック、修飾キー+クリック、
  あるいは「選択モード」ボタンを出すのか。`T03` が左swipeを退けたのと同じ論点である。
- **`T09`(表示モード)や `T25`(通知)と衝突しないか。**

## 現行実装から分かったこと(2026-09-19)

- 行の **×** は**元場所ハンドルを持つ行にだけ**出る(004 REQ-006。`file_list_view.dart` の
  `onRemove` は `handle == null` で `null`)。
- 行の**つまみは連番トークンがあるときだけ**出る(002 REQ-014。`controller.manualOrderMatters`)。
  **つまり、つまみと × が隣り合うのは「連番を含むルールを設定した後」だけである。**
  ルールが空の初期状態や、連番を使わないルールでは × しか出ないので、**押し間違いが起きうる
  場面は常時ではない**。提案の動機(押し間違い)はこの場面に限られるが、
  **「まとめて外せない」ほうは常時の不便である**(現在は部分的にまとめて外す手段が無く、
  帯の「一覧を空にする」で全部空にするしかない)。
- ヘッダは現在 `〇 件` と警告件数だけを出す(`T03` で全選択トグルと「n/n 件を選択」を撤去した)。
- 長押しはFlutterではマウスでも発火する。**問題は操作可否ではなく発見可能性**である
  (押せることが画面から読めない。screen readerでも辿りにくい)。

## 枠組みの案(2026-09-19。人間へ提示)

### 案A: 長押しの選択モード + ヘッダに常設の入口。通常モードの行 × は撤去する(推奨)

- 通常モードの行は **× を持たない**。除去は「選択モードへ入る → 行を選ぶ → `リネーム候補から外す`」。
- モードへ入る口は**2つ**: 行の長押し(近道)と、**ヘッダの常設button**。
  後者があるので、長押しの発見可能性とdesktop/screen readerの代替が**同じ一つの仕組みで済む**
  (`T03` が左swipeを退けた理由は代替が別に要ることだった。ここでは要らない)。
- 押し間違いは**構造的に消える**(通常モードにはつまみしか無い)。まとめて外せる。行も軽くなる(`T10`)。
- 代償: **1件外すのに3手**になる(長押し → その行を選ぶ → 外す)。長押しした行を最初から
  選択済みにすれば2手になる。

### 案B: × とつまみを離すだけ(最小)

- × を行の**左端**へ、つまみだけ右端へ置く。1手のままで、距離で誤タップを減らす。
- **まとめて外す手段は増えない**(常時の不便は残る)。× が現在名の左に来るので行の読み始めが濁る。

### 案C: 案A + 通常モードの行 × も残す

- 1件は1手、複数はモード。**ただし × とつまみは隣り合ったままなので、提案の主目的(押し間違いの
  根絶)が達成されない**。× を左端へ移す(案B)と併せれば両立するが、除去の入口が2つになる。

## 残りの「決めること」への現時点の案(案Aを採る場合)

- **REQ-016 の改訂**: 「行 UI は選択の切り替えを提示しない」を**「通常の一覧表示では提示しない」**へ
  限定し、**除去のための一時的な選択モードを別の要求(REQ-018 案)として足す**。
  一覧＝rename対象という不変は変えない — モード中の選択は**外す候補**であり、
  モードを抜けると選択は消え、一覧の中身は変わらない。代表例 6e は「通常表示では checkbox が無い」へ。
- **モード中のつまみ**: **隠す**。モードは外す作業に専念させる(押し間違いを消すのが目的なので、
  モード中に並び替えを残すと目的が半分戻る)。並び替えはモードを抜けてから行う。
- **ヘッダの文言**: `〇件選択中` は「rename 対象の選択」と読まれうる(`T03` で UI から
  「選択」を消したばかり)。**見出しを「外すファイルを選ぶ」**とし、件数は `3件`、
  実行buttonは提案どおり **`リネーム候補から外す`**(結果を名指しするので誤読しにくい)。
  左は × (やめる)。0件のときは実行buttonを押せない。
- **取り消し(REQ-017)**: まとめて外した分は**1回の取り消しで全部、元の位置へ**戻る
  (「直前の除去」を1回の除去操作として読む)。外し終えたらモードを自動で抜ける。
- **帯の「一覧を空にする」**: そのまま残す(全部空にする近道)。
- **`T09` / `T25` との関係**: `T09`(表示モード)は後着手なので、どの表示モードでも同じ入口が
  必要であることを `T09` 側が読む。`T25`(通知を閉じる)は取り消しtoastの見せ方だけなので衝突しない。

## 決定(2026-09-19・開発者)

**枠組みは案A。** 002 spec を次のように改訂し、開発者が再承認した。

- **REQ-016 を通常表示に限定**し、「**通常表示では 1 件ごとの除去操作も提示しない**」を足した(× の撤去)。
- **REQ-018 を新設**した。入口は長押しと**長押しに依存しない常設の入口**の2系統、長押しで入った行は
  選択済み、件数が読める、0 件では外せない、**モード中は並び替えを見せない**、やめると選択は破棄され
  一覧は変わらない、**1 回の取り消しで全件が元の位置へ**戻る。
- **代表例 6f〜6j を追加**し、6e を「通常表示では × も出ない」へ改めた。
- `T03` の決定節にあった「**行の × を、除去の唯一の導線として残す**」は取り消し線で差し替えた。
  左 swipe を採らない理由(代替導線が別に要る)はそのまま有効である。
- **状態層(REQ-004/008/009)と 004 のポート契約は変えていない。**

文言・見た目・アニメーションは縛らず、決定節へ「見出しは『外すファイルを選ぶ』のように外すことを
名指しする」理由だけを残した(`〇件選択中` だけでは「選んだものを rename する」と読まれうる)。

実装は [`T28`](../T28-implement-removal-selection-mode/task.md)(`covers`: 002 REQ-016 / REQ-017 / REQ-018)。
