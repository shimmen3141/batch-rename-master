# T24 folderで行を束ねる案を定義する

## 目的

複数folderのファイルが一覧に混ざるときの見せ方を、**行ごとの副題**から
**folder行で束ねる形**へ変えるかを決める。決めるところまでがこのtaskで、実装は別taskへ分ける。

## 受領した要望(2026-09-18、原文)

> 要望1: 複数フォルダにまたがる場合、各行の詳細にフォルダ名を書いても見づらいので、フォルダの行を追加する案を思いつきました。以下のようにフォルダ行(名前だけの行なので縦幅は小さくてよい)で各ファイルをまとめ、各ファイルはフォルダ行に対して少しインデントさせるイメージです。また、フォルダ行をクリックすることで、配下のファイルを非表示にできたりするとよいです(フォルダ行のアイコンのフォルダが開いたものになったり閉じたものになったりする。ファイルがフォルダ行にしまわれるようなアニメーションがあるとユーザもイメージしやすい)。
>
> - フォルダA
>   - ファイルA-1
>   - ファイルA-2
> - フォルダB
>   - ファイルB-1
>   - ファイルB-2

観測の出所は [`T08`](../T08-load-affordance-and-path/task.md) の
「manual確認の結果(2026-09-18。2回目)」。

## 先に確かめるべき前提(未解決)

**いまこの案が効く経路が製品に無い。** Android は 004 REQ-016 で**1 folder内の選択に限られ**、
Windows desktop の picker も folder を跨げない
(`development-findings/2026-09-18-desktop-picker-cannot-span-folders-so-the-multi-folder-path-is-unreachable.md`)。
したがって、

1. **複数folderの混在を製品経路から到達可能にするか**(004 REQ-016 / REQ-012 の見直し)
2. それを**しない**なら、この案は将来の保険として仕様だけ決めるのか、**やらない**のか

は開発者の判断である。

### 開発者の決定(2026-09-18)

> 複数フォルダの混在を製品経路から到達可能にはしません。T24は、もしそのような経路があったとしても
> UIを良いものにするものという位置づけで、優先度は低めです。

- **1は「しない」で確定した。** 004 REQ-016(1 folder内の選択に限る)と REQ-012(跨ぎ警告)は
  **変えない**。
- **2は「やらない」ではない。** このtaskは閉じずに `pending` のまま残す。**位置づけは
  「到達できる経路があったときにUIを良くするもの」**で、**優先度は低い**。
  他に実行可能なtaskがある間は着手しない。
- したがって、いま到達できるのは **demo dataの初期値だけ**である(`008:T23` で2 folderに分けた)。
  この案を検討・確認する足場はそこにある。

## 追加で受領した案(2026-09-19、原文)

> T29とはあまり関係ない思い付き: 複数のフォルダが選択されたときにフォルダの行をファイル行と一緒に表示するという案を出していたと思いますが、1つのフォルダの場合でも同様にフォルダ行を表示するとよいかもしれません。なぜかというと、そのフォルダ行から、同じ選択状態・同じフォルダに即座に飛んでファイルを追加する導線をつくりやすいためです。また、複数選択時と単一選択時でUIが統一されるという実装上の利点もあります。なお、上部にある選択中のフォルダの表示は、フォルダを選択しなおすための導線として維持します。

**このtaskの前提が変わる。** 起票時は「複数folderが混ざるとき」の案で、
**製品経路から到達できない**ことが低優先度の理由だった(2026-09-18 の決定)。
**1 folder でも folder 行を出すなら、製品経路に常に載る** — 低優先度の理由が消える。

あわせて次を決める必要がある。

- **[`T26`](../T26-define-picker-state-restore/task.md) との関係。** folder 行が
  「**同じ選択状態・同じ folder へ飛んでファイルを追加する**」導線の置き場所になる。
  `T26` は仕様定義から始まる task なので、**どちらが導線の置き場所を決めるか**を先に切る
  (案: `T26` が「復元して追加する」振る舞いを定義し、`T24` が folder 行という提示を定義する)。
- **行の場所のサブ情報(002 REQ-010 / `T22` の決定)と重複しないか。** `T22` は
  「**複数の場所が混ざるときだけ行に出す**」と決めた。folder 行が常に出るなら、
  行のサブ情報としての場所は**常に不要**になりうる。002 の決定節の改訂と再承認が要る。
- **上部の帯は維持する**(folder を選び直す導線。開発者が明記した)。
- **`T28` の選択モード(002 REQ-018)との関係。** folder 行は選べるのか(folder ごと外せるのか)、
  選択件数に数えるのか。数えるなら「件数と実行結果の食い違い」を作らない形にする。
