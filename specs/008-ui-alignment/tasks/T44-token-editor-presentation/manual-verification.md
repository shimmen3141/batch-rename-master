# 手動確認: トークンの設定を参考デザインのダイアログへ(Androidエミュレータ)

**対象buildは、`lib/`・`hook/`・`src/`の内容が task.md の「Evidence revision」に書いた code commit と同一のもの**である。branch `asdd/008-ui-alignment/T44-token-editor-presentation` のHEADからbuildすればこれを満たす。**code・dependency・build設定が変わったら、この結果は再利用しない。**

**Androidエミュレータで確認する**(`008:T39`で開発者が決めた方針)。見た目と操作を見るので debug build でよい。見比べる参考デザインは`docs/design/Bulk Renamer.html`(ブラウザで開き、ルール設定から「＋ 連番」などを押すとダイアログが出る)。

## 使う端末と準備

- host側でworktree `.worktrees/008-T44-token-editor-presentation` へ`cd`してから`flutter pub get` → `flutter run`する(branchの移動は不要)。共通の手順は[`docs/development/emulator-verification.md`](../../../../docs/development/emulator-verification.md)。
- ファイルは`008:T25`のfixture(`Download/asdd-008-t25`の3件。改名後の名前でもよい)を使う。**無ければ**、[`008:T25`の手順書](../T25-dismissible-toast/manual-verification.md)の「準備するファイル」を実行する。
- 「ファイルを選ぶ」→「すべて」→ `Download` → `asdd-008-t25` で3件を選んで確定する。
- 下の「**命名ルール**」のボタンを押してルールのシートを開く(シートそのものの見た目は`T45`で整えるので、このtaskでは見ない)。

## 1. 形(中央のダイアログ)

1. シートの「**＋ 連番**」を押す。
   - 画面の**中央に角丸のダイアログ**が出る(下から出るシートではない)。後ろが暗くなる。
   - 上に見出し「**連番**」と説明「**リネームリスト一覧の上から順に番号を振ります。**」。下端に「**キャンセル**」「**追加**」が横に並ぶ(追加のほうが広い)。
2. ダイアログの**外**(暗い所)を押す。
   - ダイアログが閉じ、ルールは変わらない。

## 2. 連番

1. もう一度「＋ 連番」を押す。
   - 上から「**ゼロ埋め**」(スイッチ)「開始番号」「桁数」「増分」の順に並ぶ(**ゼロ埋めが開始番号の上**)。−/＋ は**枠のついた四角いボタン**で、値は**シアン**の太字。
   - 区切り線の下に「**表示例（一覧の 3 件に上から順に振られます）**」と、**緑**で `01 ～ 03`。
2. 開始番号の「＋」を1回押す。
   - 表示例が `02 ～ 04` になる。
3. ゼロ埋めをOFFにする。
   - 「桁数」の欄が消え、ダイアログの高さが**滑らかに**(一瞬で切り替わらずに)縮む。表示例が `2 ～ 4` になる。
4. ゼロ埋めをONに戻す。
   - 「桁数」の欄が戻り、高さが**滑らかに**伸びる。
5. 「キャンセル」で閉じる。

## 3. 日時

1. 「**＋ 日時**」を押す。
   - 見出し「日時」、説明「**基準となる日時とフォーマットを選んでください。**」。
   - 「**基準**」(作成日時 / 更新日時 / 現在日時)と「**フォーマット**」(`YYYYMMDD` などのチップと、最後に「**詳細に記述**」)が並び、選ばれているチップは**シアンの枠と文字**。**入力欄は出ていない**。
   - 表示例の見出しが「表示例（1つ目のファイルの作成日時）」で、**一覧の1件目**の作成日時が緑で出る(作成日時が取れないファイルなら「（日時が不明）」)。
2. 基準を「更新日時」、フォーマットを `YYYY-MM-DD` にする。
   - 表示例が1件目の更新日時で、`2026-09-29` のような形に変わる。
3. 「**詳細に記述**」を押す。
   - 入力欄が出て、ダイアログの高さが**滑らかに**伸びる。入力欄には**直前に選んでいた `YYYY-MM-DD` が入っている**。「詳細に記述」が選ばれ、`YYYY-MM-DD` のチップは選ばれていない表示になる。
4. 入力欄を押してキーボードを出す(画面キーボードが出る設定にしておく)。
   - ダイアログがキーボードに隠れず、欄が見える。ダイアログの中を上下に**スクロール**でき、「基準」から「追加」まで順に見られる。
   - 末尾に `_` を足すと、表示例が追随する(例: `2026-09-29_`)。
5. `YYMMDD` のチップを押す。
   - 入力欄が消え、高さが**滑らかに**縮む。表示例が `YYMMDD` の形になる。
6. 「追加」を押す。
   - シートに「日時 YYMMDD」が加わる。
7. 加わった「日時 YYMMDD」を押して開き、「詳細に記述」を押して入力欄を `YYYY年MM月DD日` に書き換えて「確定」。もう一度開く。
   - プリセットに無いフォーマットなので、**「詳細に記述」が選ばれ、入力欄が出た状態**で開く。欄には `YYYY年MM月DD日`。

## 4. 自由テキストと区切り

1. 「**＋ 自由テキスト**」を押す。
   - 見出し「**自由テキスト**」、説明に「区切り文字（"_"や"-"）も含められます。」。入力欄(暗い面にシアンの枠。空のときは `"作成資料" や "旅行_" など` と薄く出る)と「**記号**」のチップ(ハイフン - / アンダーバー _ / 半角空白 ␣ / 全角空白 ␣)。
   - 何も入れないと「追加」は押せない。
2. 「キャンセル」で閉じ、「**＋ 区切り**」を押す。
   - 見出しが「**区切り文字**」。
3. 「アンダーバー _」を押して「追加」。シートに加わった `_` を押す。
   - 見出しが「**自由テキスト / 区切り文字**」で、「アンダーバー _」のチップが選ばれている。ボタンは「**確定**」。

## 5. 広幅(任意)

エミュレータを横向きにして2ペインにし(幅が足りない端末なら省く)、右のルールから「＋ 連番」を押す。

- ダイアログが画面の中央に出て、横に広がりすぎない(幅はおよそ420まで)。
