# 手動確認: 実行前の確認ダイアログ(Androidエミュレータ)

`008:T14` で作り直した**実行前の確認ダイアログ**を、実機の字体と幅で確かめる。

**対象buildは、`lib/`・`hook/`・`src/`の内容が commit `6d2f56d` と同一のもの**である。branch
`asdd/008-ui-alignment/T14-modal-wording-and-presentation` のHEADからbuildすればこれを満たす。
**code・dependency・build設定が変わったら、この結果は再利用しない。**

種類ごとのまとめ方、文言、実行buttonの色、件数が多いときにbuttonが画面に残ること、名前が変わった結果の
詳細は、自動testで確かめてある。ここで見るのは**実機で読んで分かりやすいか**と、**本当に改名されるか**である。

**ここで見ないもの**(自動testだけで確かめる):

- **名前が変わった結果の詳細**(通知の「名前を確認する」から開くダイアログ)。実行の**最中に**別のアプリが
  同じ名前のファイルを作ったときにだけ出るので、手では再現できない。
- **「名前が空」の枠**。名前が空になるには日時だけのルールで日時が取れないファイルが要るが、そのルールでは
  ほかのファイルも名前が変わらず実行buttonが押せないので、実機では確認ダイアログまで届かない。
- **「桁不足」の枠**。連番の桁はファイル数に合わせて自動で引き上がるので、画面からは出ない。

## 使う端末と準備

- 起動と`flutter run`は`/workspace/docs/development/emulator-verification.md`のとおり。branchの移動は不要
  (`/workspace` はすでにこのbranchにある)。host側で`flutter pub get` → `flutter run`する。
- 「すべてのファイルへのアクセス」は許可しておく。

**捨ててよいファイルを12個**、端末の `Download/asdd-008-t14` に置く。host の PowerShell から:

```powershell
$adbPath = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
$fixturePath = Join-Path $env:TEMP 'asdd-008-t14'
Remove-Item -Recurse -Force -LiteralPath $fixturePath -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path $fixturePath | Out-Null
1..12 | ForEach-Object { Set-Content -LiteralPath (Join-Path $fixturePath ('photo_{0:D2}.txt' -f $_)) -Value "t14-$_" }
& $adbPath shell "rm -rf /sdcard/Download/asdd-008-t14 && mkdir -p /sdcard/Download/asdd-008-t14"
& $adbPath push "$fixturePath/." /sdcard/Download/asdd-008-t14/
& $adbPath shell ls /sdcard/Download/asdd-008-t14
```

**期待**: 最後の `ls` に `photo_01.txt` 〜 `photo_12.txt` の12個が出る。

**読み込み**: アプリの「別フォルダへ」(初回は「ファイルを選ぶ」)→「すべて」→(保存場所の一覧が出たら「内部ストレージ」)→
`Download` → `asdd-008-t14` へ入り、「すべて選択」→「確定」。一覧に12件が並ぶ。
ルールが前回のまま残っていたら、チップを全部消してから始める。

## 0. いま動いているのが、このbuildか確かめる

手順1の操作で出るダイアログの見出しが **「実行前の確認」** なら、このbuildである
(前の build は「警告を確認してください」で、警告が1件ずつ「•」で並んでいた)。

## 1. 名前が重なるとき(重複)

1. 「命名ルールを設定する」→「＋ 自由テキスト」で `same` と入れて「追加」し、一覧へ戻る。
2. 「12 件をリネーム」を押す。

**こうなってほしい**

- 中央にダイアログが出て、見出しが「実行前の確認」、その下に「12 件のファイルに問題があります。
  このまま実行すると、次のように処理します。」とある。
- 薄い赤の枠が**1つだけ**あり、「重複 12 件」と、「重ならないように、名前の末尾へ (1) (2) … を付けて
  改名します」と、対象の12個の名前が読める。**同じ文が12回並んでいない。**
- 下に「キャンセル」と赤い「自動解決して実行」が横に並ぶ。**赤いほうが「警告を押し切る」操作だと
  見分けられる。** 文字が切れていない。
- **何を聞かれていて、押すと何が起きるかが、このダイアログだけで分かる。**(分かりにくい言い回しが
  あれば、その文を教えてほしい)

3. 「キャンセル」を押す。

- ダイアログが閉じ、一覧の名前は変わっていない(PowerShell で
  `& $adbPath shell ls /sdcard/Download/asdd-008-t14` を実行しても12個とも元の名前)。

4. もう一度「12 件をリネーム」→「自動解決して実行」を押す。

- 「12 件を改名しました」という通知が出て、5秒ほどで自然に消える。
- PowerShell の `ls` で、`same.txt`、`same (1).txt` 〜 `same (11).txt` の12個になっている。

5. 通知が出ている間に「元に戻す」を押す(間に合わなければ、上の準備のコマンドを最初から実行し直して
   置き直し、アプリで読み込み直す)。

- `ls` で `photo_01.txt` 〜 `photo_12.txt` に戻っている。

## 2. 日時が取れないとき(作成日時不明)

端末のファイルは作成日時が取れないので、日時の部分は空になる。名前が変わるように、間に固定の文字を挟む。

1. ルールのチップを全部消し、「＋ 元の名前」→「＋ 自由テキスト」で `_` を「追加」→「＋ 日時」(基準は作成日時の
   まま)を足して一覧へ戻る。変更後の名前が `photo_01_.txt` のようになっている。
2. 「12 件をリネーム」を押す。

**こうなってほしい**

- 枠が1つで、「作成日時不明 12 件」と、「その日時の部分を空にして改名します」が読める。
- 実行buttonの文言が **「このまま実行」**(何も自動では解決しないので「自動解決」と書かない)。

3. 「キャンセル」を押す。名前は変わっていない。

## 3. 狭い幅・大きな文字(任意)

端末の設定で文字のサイズを最大にし、手順1の2までをもう一度行う。

- ダイアログの見出しと、下の2つのbuttonが画面に収まっている。対象の名前が多くても、
  **枠の部分だけが縦に動き**、buttonは押せる位置に残る。
