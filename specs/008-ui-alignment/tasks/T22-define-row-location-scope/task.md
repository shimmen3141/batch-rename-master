## 衝突する正本

- **002 `spec.md`「004由来の更新(2026-08-04・開発者再承認済み)」**: 「場所のサブ情報: 各行に元folderを
  副題として供給(REQ-010)。`FileEntry.sourceLocation`(001で追加)を用いる。**同名・非同名に関わらず常時表示。**」
- **同 実装方針・検査**: `test/spec_002_file_list/location_view_test.dart` の
  「**同名でなくても場所は常時表示される(REQ-010)**」ほか、VER-002 の3件が行の場所を固定している。

**REQ-010 の must 自体とは衝突しない。** REQ-010 が課しているのは「行データが表示用の場所を保持し、
行UIがサブ情報として**表示できる形で供給する**」ことで、**データの供給は改訂後も変わらない**。
代表例7も「供給される」と書いている。硬い衝突は上の決定文(表示の側)と、そこから来た検査にある。

## 決めたこと(開発者の選択。2026-09-18)

3案(複数folderのときだけ出す / 常時表示のまま / 無条件に消す)を示して**「複数folderのときだけ行に出す」**を選んだ。

- **同一folderのとき**: 行に場所を出さない。**一覧全体として1か所**(読み込み帯)に出す(要望11)。
- **複数folderが混ざるとき**: 行に**そのfileのfolder名**を出す(要望12の後半)。帯は具体名を出さず、
  複数であることだけを示す(要望12の前半)。

Androidは004 REQ-016で選択が同一folder内に限られるので**常に前者**、desktopは「すべて」「文書」が
OSのpickerを開くので後者になりうる。

## 改訂案(002 `spec.md`)

決定文を次へ置き換え、**代表例を1件足す**。REQ-010 の行は変えない(供給の要求は不変)。

> **場所のサブ情報**: 各行に元folderを副題として**供給**する(REQ-010)。`FileEntry.sourceLocation`
> (001で追加)を用いる。**行UIがそれを表示するのは、一覧に複数の場所が混ざっているときだけ**である
> — 場所が1つだけなら一覧全体として1か所に示せば足り、全行へ同じ名前が並ぶのは冗長である
> (2026-09-18 開発者決定。要望11・12)。**混ざっているときは行ごとに表示して、どの行がどの場所の
> ものか見分けられるようにする。**
