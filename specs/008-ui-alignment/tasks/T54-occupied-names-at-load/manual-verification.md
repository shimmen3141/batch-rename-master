# 手動確認: 読み込み時の占有名(Androidエミュレータ)

`008:T54` で、**読み込んだ時点で**フォルダにあるファイルの名前を調べるようにした。読み込んでいないファイル
(フォルダにもともとある同名)との重複が、**実行buttonを押す前から**一覧に出ることを、実機で確かめる。

**対象buildは、`lib/`・`hook/`・`src/`の内容が commit `20eb3b1` と同一のもの**である。branch
`asdd/008-ui-alignment/T54-occupied-names-at-load` のHEADからbuildすればこれを満たす。
**code・dependency・build設定が変わったら、この結果は再利用しない。**

問い合わせる時機(読み込み・読み込み直し・改名の後だけ。選択やルールの変更では問い合わせない)、選択を変えても
偽の重複が出ないこと、取れなかったときに繰り返さないことは、自動testで確かめてある。ここで見るのは
**実機のフォルダで本当に名前が取れるか**と、**数千件のフォルダでも待たされないか**である。

## 使う端末と準備

- 起動と`flutter run`は`/workspace/docs/development/emulator-verification.md`のとおり。branchの移動は不要
  (`/workspace` はすでにこのbranchにある)。host側で`flutter pub get` → `flutter run`する。
- 「すべてのファイルへのアクセス」は許可しておく。

端末の `Download/asdd-008-t54` に、**中身の無いファイルを5000個と、確認に使う2個**を置く。host の PowerShell から
(5000個を作るのに数十秒かかることがある):

```powershell
$adbPath = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
& $adbPath shell 'rm -rf /sdcard/Download/asdd-008-t54 && mkdir -p /sdcard/Download/asdd-008-t54 && cd /sdcard/Download/asdd-008-t54 && i=1; while [ $i -le 5000 ]; do : > bulk_$i.txt; i=$((i+1)); done; echo t54 > a_target.txt; echo t54 > same.txt'
& $adbPath shell 'ls /sdcard/Download/asdd-008-t54 | wc -l'
```

**期待**: 最後の行に `5002` が出る。

**読み込み**: アプリの「別フォルダへ」(初回は「ファイルを選ぶ」)→「すべて」→(保存場所の一覧が出たら「内部ストレージ」)→
`Download` → `asdd-008-t54` へ入る。**`a_target.txt`(一番上にある)だけを押して選び**、「確定」。一覧に1件だけが並ぶ。
ルールが前回のまま残っていたら、チップを全部消してから始める。

## 0. いま動いているのが、このbuildか確かめる

手順1で、**実行buttonを一度も押していないのに** `a_target.txt` の行に「重複」が出れば、このbuildである
(前の build は、実行buttonを押して確認を閉じるまで出なかった)。

## 1. 実行buttonを押す前から重複が出る

1. 「命名ルールを設定する」→「＋ 自由テキスト」で `same` と入れて「追加」し、一覧へ戻る。

**こうなってほしい**

- `a_target.txt` の行の右端に「重複」が出る。一覧の上が「リネーム: 1 件の問題 詳細」。
- 行の「重複」を押すと、詳細の枠に `a_target.txt`、赤の `→ 「same.txt」`、赤の「(フォルダにある既存のファイルと重複)」。
- **実行buttonはまだ押していない。**

2. 「閉じる」で閉じる。

## 2. 数千件のフォルダでも待たされない

手順の「読み込み」(「確定」を押してから一覧が出るまで)と、手順1でルールを足してから「重複」が出るまでについて:

**こうなってほしい**

- 「確定」の後、一覧がいつもどおりすぐ出て、スクロールやボタンの操作が止まらない。
- 「重複」は**ほぼすぐ**出る(おおよその秒数を教えてほしい。1秒を超えて待たされるようなら、その旨も)。

## 3. ルールを変えると、それに合わせて出たり消えたりする

1. ルールのチップを全部消し、「＋ 自由テキスト」で `other` を足して一覧へ戻る。

- 「重複」が消える(`other.txt` はフォルダに無い)。

2. もう一度チップを消して `same` に戻す。

- 「重複」がまた出る。

## 4. 実行と元に戻すが今までどおり動く

1. 「1 件をリネーム」→ 確認で「自動解決して実行」。

- 「1 件を改名しました」が出る。一覧の名前は `same (1).txt`。PowerShell で
  `& $adbPath shell 'ls /sdcard/Download/asdd-008-t54 | grep -v bulk_'` を実行すると `same (1).txt` と `same.txt`。

2. 通知が出ている間に「元に戻す」を押す。

- 一覧の名前が `a_target.txt` に戻り、行に「重複」が出たまま(ルールは `same` のまま)。
