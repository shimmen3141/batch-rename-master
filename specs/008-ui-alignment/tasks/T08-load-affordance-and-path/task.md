### Androidの前提が変わった(2026-08-22 / `013:T03`)

**下の「先に解く設計上の食い違い」はdesktopにだけ当てはまる。** `013:T03`が004 specへREQ-016を足し、**Androidのapp内file browserでは選択が同一folder内に限られる**ようになった(folderを移動すると選択が解除される)。したがってAndroidでは:

- **「選択中のfolder」が存在する**(常に1つ)。「無い状態が通常」ではない。
- **複数folder警告(004 REQ-012)は発火しない。** 「通常経路で起きる」もdesktopの話になった。
- 種類は「画像」「動画」「すべて」の3つで、**「文書」が無い**(REQ-011)。

**着手前に[`013:T03`のtask.md](../../../013-safe-android-rename/tasks/T03-define-android-file-browsing/task.md)と004 specのREQ-011・REQ-015〜019を読むこと。** platformで提示を分けるか、両方に成り立つ形にするかを決める必要がある。

### 先に解く設計上の食い違い

参考designは「フォルダを選択 / 別フォルダへ」という**folder単位のmodel**を前提にしている。しかし004は決定D-2で**file複数選択**を採っており、さらにAndroidのDocumentsUIは種類chipがfolderを横断する(上記finding)。**現実には「選択中のfolder」が存在しない状態が通常**である。

したがってdesignの文言をそのまま写さない。folderを選んだかのように見せる導線は、実際の挙動と食い違う。**004の契約に正直な提示**を設計し、`task.md`へ根拠を書く。

## 着手時に調べたこと(2026-09-18)

### 要望12の前提は、いまのAndroidでは起きない

- 004 REQ-011 で **「画像」「動画」は枠のみ**(選んでも読み込まず「未実装(写真機能で対応)」を出す)。
  要望12の「画像や動画でフォルダをまたぐ場合」は、**Androidでは現状発生しない**。

### 参考designから離れる点

- designの読み込み帯は `folderLabel: loaded ? '内部ストレージ / DCIM / Camera' : '未選択'` という
  **pathの連鎖**を出す。**004が供給するのは表示用のfolder名1つ**である(REQ-002 はハンドルを不透明値と
  定め、パスとして解釈してよい保証を置いていない。root の basename が `0` になる件も `main.dart` が
  保存場所名で補っている)。**ヘッダにはfolder名1つを出す**。連鎖を出すには browser 側が経路を供給する
  必要があり、004の契約を広げることになるので、このtaskではやらない。
- designの `pickLabel` は `'別フォルダへ' : 'フォルダを選択'` だが、**文言は開発者の指定
  (『別フォルダへ』/『ファイルを選ぶ』)を優先する**(task.mdの要望11のとおり)。

## 行の場所の扱い(開発者の決定。2026-09-18)

3案を示し、**「複数folderが混ざるときだけ行に出す」**(案A)が選ばれた。

- **同一folder**(Androidは常にこれ): 行に場所を出さず、**読み込み帯が1か所で示す**。
- **複数folderが混ざる**(desktopのみ): 行に**そのfileのfolder名**を出し、帯は具体名を出さず複数であることだけを示す。

002の決定文の改訂と再承認が要るので、**仕様更新は[`T22`](../T22-define-row-location-scope/task.md)が持つ**
(`plan.md`の「仕様を変えるものは仕様更新taskと実装taskを分ける」)。**このtaskは`T22`の再承認を受けてから
行の側を実装する。** 帯とbuttonの文言は承認を待たない(002/004のどの要求も変えないため)。
