# 手動確認: すべてのファイルへのアクセスの許可導線

この文書は、**実機でしか分からないこと**だけを扱う。画面の出し分けや、許可が無いときに
ファイルへ触らないことは自動テストで確かめてあるので、ここには含めない。

見てほしいのは、実際に許可が付いたり外れたりするか、設定画面へ本当に飛ぶか、
戻ったときに画面へ反映されるか、文言が読めて意味が伝わるか、である。

## 使う端末

**Android 11 以上**の端末またはエミュレータを使う。「すべてのファイルへのアクセス」は
Android 11 で入った設定で、それより古い端末には**存在しない**。

起動手順は [`docs/development/emulator-verification.md`](../../../../docs/development/emulator-verification.md) に従う。

設定画面でこのアプリを探すときの名前は **`batch_rename_master`** である。
アプリを開いたときに上に出る「一括リネーム」や、履歴画面の「一括リネーム(デモ)」とは
別の名前なので注意してほしい。

## 各手順を始める前に

端末の「設定」→「アプリ」→ `batch_rename_master` →「すべてのファイルへのアクセス」を
**オフに戻してから**始める。

## 1. 許可がない状態でファイルを選ぼうとする

1. 許可をオフにした状態でアプリを起動する。
2. **起動した直後**の画面を見る。
3. 「ファイルを選ぶ」を押す。

**こうなってほしい**

- 起動しただけでは**設定画面へ飛ばない**。
- 「ファイルを選ぶ」を押すと、**ファイルの種類を選ぶシートが開かず**、画面の上に
  「ファイルの名前を安全に変更するには、端末の『すべてのファイルへのアクセス』が
  必要です。…」という説明と、「設定を開いて許可する」ボタンが出る。
- **押しただけで設定画面へ飛ばされることはない**(飛ぶのは次の手順のボタンを押したとき)。

**見てほしい点**: 説明を読んで「なぜこの許可が要るのか」が伝わるか。伝わらなければ、
どこが分かりにくいかを書いてほしい。

## 2. 設定画面へ行って許可し、戻る

1. 「設定を開いて許可する」を押す。
2. 開いた設定画面で、このアプリの「すべてのファイルへのアクセス」を**オンにする**。
3. 端末の戻る操作でアプリへ戻る。
4. 「ファイルを選ぶ」を押す。

**こうなってほしい**

- ボタンを押すと、**このアプリの**「すべてのファイルへのアクセス」の画面が直接開く。
  アプリの一覧が開いた場合は、そこからこのアプリを探して続けてよい。
  **どちらが開いたかを書いてほしい**(端末によって違うことが分かっている)。
- アプリへ戻ってきた直後、**説明が消えている**。「ファイルを選ぶ」を押し直さなくても消える。
- そのあと「ファイルを選ぶ」を押すと、ファイルの種類を選ぶシートが開き、ファイルを選べる。

## 3. 許可せずに戻ってきたとき

1. 許可をオフに戻し、「ファイルを選ぶ」を押して説明を出す。
2. 「設定を開いて許可する」を押し、**何も変えずに**アプリへ戻る。
3. もう一度「ファイルを選ぶ」を押す。

**こうなってほしい**

- 説明と「設定を開いて許可する」が**出たまま**である。消えない。
- 押すたびに設定画面へ勝手に飛ばされる、ということにはなっていない。

## 4. 狭い画面での見え方

1. 許可をオフにして説明を出した状態で、**縦向き**のまま、あるいは画面分割で見る。

**こうなってほしい**

- 説明文が途中で切れず読める。「設定を開いて許可する」ボタンが押せる位置にある。
- 説明が画面を占領しすぎて、下の操作が使えなくなっていない。

## この確認に含めていないこと

**ファイルの名前を実際に変更する手順は入れていない。** いまの版の Android では、
名前の変更を始める前に「フォルダの中のファイル名を確認する」段階で止まる作りになっており、
許可の有無に関係なくそこで終わる。許可を途中で外したときの動きは、**アプリ内で
フォルダを辿れるようになってから**(`013:T07`)まとめて確認する。
