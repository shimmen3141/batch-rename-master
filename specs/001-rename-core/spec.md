# コア命名エンジン(rename-core) 振る舞い仕様

- Status: approved(2026-07-26 開発者承認。正本の承認状態は `contracts/behavior-contract.json` の `status`)
- Level: Strict(**正本は `contracts/behavior-contract.json`**。本ファイルは説明・図解・代表例・反証ログを担い、正誤判定は契約が行う)

## 目的(説明的・正誤判定には使わない)

一括リネームの中核。ファイルのメタデータとトークン列(元名・リテラル・連番・日時)を入力に、生成後名の構成・プレビュー・ドライラン検証(重複/桁不足/空名)・自動解決を、UI とファイルIOから分離した純粋 Dart として提供する。ファイルを破壊しうる操作の正しさをここで固定する。Why/Why not は `decisions/` の ADR を参照。

## 境界

- 対象(in scope): 契約 `scope.in` を正とする。トークン評価・プレビュー生成・ドライラン検証・自動解決。
- 対象外(out of scope): 契約 `scope.out` を正とする。実ファイルIO・SAF・OS別禁止文字検証・UI・トークン既定値。
- アクター: 呼び出し側(UI 層 002/003)。
- 入力: `RenameRule`、`List<FileEntry>`(各 name・作成/更新日時・サイズ・選択フラグ)、`now`(現在日時)。
- 出力: 生成後名、プレビュー、警告リスト、自動解決後の最終名。
- 永続化される状態: なし(純粋関数群)。
- 外部副作用: なし(INV-004。ファイルシステムへアクセスしない)。

## 振る舞い

正規の規範は契約の REQ/INV/OP。以下は理解のための場合分け・性質・代表例。

### 場合分け(トークン評価: REQ-001〜005)

- 元名トークン → ベース名(name の最後のドットより前。先頭ドットは境界としない)。
- リテラルトークン → 設定文字列そのまま(区切り記号もこれ)。
- 連番トークン → `開始 + (position-1)×増分` を桁数までゼロ埋め。
- 日時トークン → 基準日時を `YYYY/YY/MM/DD/HH/mm/ss`(最長一致・大小区別・ゼロ埋め)で整形、非該当文字はリテラル。
- 生成後フルネーム = トークン連結 + 拡張子後置(拡張子が空でなければ `.`+拡張子)。

### 場合分け(プレビュー/検証/自動解決: REQ-006〜012)

- プレビュー: 選択ファイルのみ・表示順保持・上から position 1,2,3…。
- 重複警告: 選択ファイルの生成後名が最終名集合(未選択の現在名 ∪ 選択の生成後名)に2回以上出現。
- 桁不足警告: 連番の計算値が `10^桁数` 以上。
- 空名警告: 生成後ベース名が空。
- 自動解決: 先頭出現は据え置き、以降の衝突に ` (n)` を付与(最小の非衝突 n)。桁不足は最大値が収まる桁へ拡張。結果の最終名集合は重複・桁不足なし。

### 性質(すべての入力で成り立つこと)

- P1(REQ-005/INV-002): 生成後フルネームは対象ファイルの拡張子で終わる(拡張子が空の場合を除く)。拡張子は変化しない。
- P2(REQ-006): プレビューの要素数 = 選択ファイル数。順序は入力の相対順を保つ。
- P3(REQ-012/INV-003): 自動解決後、最終名集合に重複はない。
- P4(REQ-013): 同一入力 (rule, files, now) に対し出力は毎回同一。
- P5(REQ-003): 連番出力の文字列長は `max(桁数, 計算値の桁数)` に等しい(ゼロ埋めは桁数まで、超過時は数字がそのまま伸びる)。

### 代表例

`ext` は元ファイルの拡張子。rule は左から順に適用。position は選択順。

| # | 入力(rule / file / position / now) | 許される出力 | 備考 |
|---|---|---|---|
| 1 | [元名] / `photo.jpg` / 1 / - | `photo.jpg` | 正常系(元名のみ、拡張子温存) |
| 2 | [リテラル `IMG`][リテラル `_`][連番 開始1 桁3] / `a.png` / 5 / - | `IMG_005.png` | 連番ゼロ埋め・区切り記号=リテラル |
| 3 | [日時 現在 `YYYYMMDD`] / `x.txt` / 1 / 2026-07-26T09:08:07 | `20260726.txt` | 日時整形 |
| 4 | [日時 現在 `YY-MM-DD_HHmmss`] / `x.txt` / 1 / 2026-07-26T09:08:07 | `26-07-26_090807.txt` | 最長一致・非該当文字はリテラル |
| 5 | [元名] / `.gitignore` / 1 / - | `.gitignore` | 先頭ドットは拡張子境界でない(ベース名全体) |
| 6 | [元名] / `archive.tar.gz` / 1 / - | `archive.tar.gz` | 拡張子は最後のドット以降のみ(base=`archive.tar`) |
| 7 | validate: [リテラル `dup`] / files=`a.jpg`(選), `b.jpg`(選) / - | 両者 `dup.jpg` を重複警告 | 選択同士の重複 |
| 8 | validate: [リテラル `keep`] / files=`x.png`(選), `keep.png`(未選) / - | `x.png` を重複警告 | 未選択の既存名との衝突 |
| 9 | validate: [連番 開始1 桁2] / 選択100件 / - | 100件目で桁不足警告 | 2桁指定・100番目 |
| 10 | validate: [リテラル ``(空)] / `a.jpg`(選、拡張子あり) / - | 空名警告 | 生成後ベース名が空 |
| 11 | autoResolve: [リテラル `dup`] / `a.jpg`(選),`b.jpg`(選),`c.jpg`(選) / - | `dup.jpg`,`dup (1).jpg`,`dup (2).jpg` | 重複の自動解決(先頭据え置き) |

## 不変条件

契約の INV-001〜004 を正とする。要点: RenameRule は任意順・重複可のトークン列(INV-001)、拡張子不変(INV-002)、自動解決後は重複なし(INV-003)、副作用なし(INV-004)。

## 異常系

| 条件 | 観測可能な結果 |
|---|---|
| 生成後名が最終名集合で重複 | validate が当該選択ファイルを重複警告として返す(REQ-007) |
| 連番が桁数に収まらない | validate が桁不足警告を返す(REQ-008)。autoResolve は桁拡張(REQ-011) |
| 生成後ベース名が空 | validate が空名警告を返す(REQ-009) |
| 選択ファイルが0件 | プレビュー・警告ともに空リスト(REQ-006 の帰結) |

## 自由とする点(実装に委ねる)

- 内部データ構造・クラス名・トークン評価の計算順序。
- Warning / PreviewEntry / ResolvedEntry の内部表現(契約が要求する識別情報を観測できれば自由)。
- 契約が規定しない書式記号(例: 曜日)は本イテレーションで未サポートとし、リテラルとして出力する。

## 対象外・未定義とする点

- OS 別の禁止文字・最大長の検証(004/005)。空名以外の名の妥当性は本仕様の対象外。
- position が 1 未満での buildName 呼び出し(事前条件違反。振る舞いは未定義)。
