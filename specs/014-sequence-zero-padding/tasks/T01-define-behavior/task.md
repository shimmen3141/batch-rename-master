# T01 ゼロ埋めの有無と桁数の下限の振る舞いを定義して承認を得る

## 目的

`008:T21`の決定を、001・003・007(と連動する002・005)の正本の差分にし、開発者の承認を得る。実装(T02〜T04)はこの承認に依存する。

## 入力と依存

- 決定の原文と選択肢: [`008:T21` の task.md](../../../008-ui-alignment/tasks/T21-define-sequence-digits/task.md)。
- 001 `spec.md`・`contracts/behavior-contract.json`(Strict): 連番の評価(REQ-003、P5)、桁不足(REQ-008)、桁の自動拡張(REQ-011)。
- 003 `spec.md`: 連番の入力範囲(「決定済み事項」の`digits ≥ 1`)、確定できない条件(REQ-012)、追加の初期値(`start:1, digits:2, increment:1`)。
- 007 `spec.md`: 連番のパラメータ(REQ-002)、必須フィールド欠損は`null`(REQ-004)、版(REQ-003)。
- 002 REQ-015・005 代表例20c/20c′: 桁不足の対象の導出(「指定桁数を超えて描かれる item」)。ゼロ埋めなしで桁不足を返さないなら文言の確認だけで済むはず — 確かめる。

## 決めること(spec差分の前に、要るものだけ開発者へ一問ずつ確かめる)

1. **ゼロ埋めなしの連番の`digits`**: 保持して評価で使わない / 持たない。エディタで桁数の欄を隠すか。
2. **下限の「件数」**: 一覧の件数(= rename対象。008:T03以後は一覧全件)でよいか。件数0のときの下限(開始番号の桁数)。
3. **件数が増えた後にエディタを開いたとき**: 桁数の欄を下限へ引き上げた値で開く / 今の値のまま開いて下限未満なら確定できない。
4. **保存の互換**: ゼロ埋めの項目を**任意**にし(無ければゼロ埋めあり)、版を上げない形で足りるか。版を上げると007 REQ-004により既存の保存が復元されずルールが消える。
5. **追加の初期値**: ゼロ埋めあり・2桁のままか。追加のエディタでも下限を適用するか。
