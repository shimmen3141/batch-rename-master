# 014 連番のゼロ埋めの有無と桁数の下限

## 目的

連番で**ゼロ埋めしない**を選べるようにし、**ゼロ埋めでは、つく名前の幅を下回る桁数を選べない**ようにする。利用者から見ると次の状態になる。

- ゼロ埋めなしの連番は `1, 2, … 10` のように数字そのままでつき、桁不足の警告は出ない。
- ゼロ埋めの連番のエディタでは、開始番号・増分・一覧の件数から決まる最大の番号の桁数より小さい桁数を選べない(20件・開始90なら最大109なので3桁以上)。
- 桁数を決めた後に件数が増えて足りなくなったときは、今と同じ桁不足の警告が行ごとに出る。連番を開くと下限に合わせて直せ、そのまま実行すれば今と同じく桁を自動で広げる。ルールを黙って書き換えない。

## 出所

`008:T21`(連番の桁数と桁不足の扱い)で開発者が決めた(2026-09-29)。観測・選択肢・決定の原文は [`008:T21` の task.md](../008-ui-alignment/tasks/T21-define-sequence-digits/task.md) にあり、ここへは複製しない。008 planの方針(判定・契約が動くときは別plan)によりこのplanを立てた。

## 境界

### 対象

- 001 `SequenceToken` にゼロ埋めの有無を足し、評価・桁不足の判定(REQ-008)・桁の自動拡張(REQ-011)をゼロ埋めの有無ごとに定める。
- 003 連番のエディタ: ゼロ埋めの切り替えと、ゼロ埋め時の桁数の下限。エディタが件数を受け取る経路。
- 007 保存形式: ゼロ埋めの有無の保存と、**それを持たない既存の保存の読み方**(利用者のルールを失わない)。
- ルールの表示(下部バーのルールの字面など、連番を文字で見せる所)がゼロ埋めなしを正しく見せること。

### 対象外

- ゼロ埋めの連番で、**全件が同じ幅なら桁不足を出さない**判定の変更(`008:T21`の案C)。開発者は採らなかった。桁不足の判定は、ゼロ埋めの連番では今のまま。
- 件数が増えたときにルールの桁数を自動で上げること(`008:T21`で採らなかった)。
- 負の連番・降順(003の決定のまま)。
- 保存schemaの版の移行の仕組み(011)。このplanは版を上げずに済む形を先に探す(T01)。

## 方針

- 外部振る舞いの正本は各planの`spec.md`とcontractのまま(001・003・007、連動するなら002・005)。このplanは`spec.md`を新設せず、**T01が既存の正本へ差分を入れて承認を得る**。001はStrict contractなので、意味の変更は人間の承認を要する。
- 桁不足の判定(001)は、ゼロ埋めの連番について変えない。**下限はエディタ(003)の入力範囲**として足す。件数が後から増えた場合の安全網は既存の警告と自動拡張である。
- 保存(007)は、ゼロ埋めの項目が無い既存の保存を**ゼロ埋めあり**として読み、今のルールをそのまま復元する。

## 全体の受け入れ条件

- [x] ゼロ埋めなしの連番を足したルールで、名前が数字そのままでつき、桁不足の警告が出ない。
  - 証拠: 001のunit test(T02。例19〜22と混在、002 例19c)、UIのwidget test(T04。例16)、Androidエミュレータのmanual(T04 手順1、2026-09-29 PASS)。
- [x] ゼロ埋めの連番のエディタで、開始・増分・件数から決まる下限未満の桁数を確定できない。件数が後から増えたときは警告が出て、実行すると桁が広がる。
  - 証拠: widget test(T04。例13〜15・17、狭幅・広幅から件数が届くこと)、Androidエミュレータのmanual(T04 手順2・3、2026-09-29 PASS)。「実行すると桁が広がる」は001 REQ-011の既存のtest(`auto_resolve_test`。T02で増分・開始番号を保つことも固定)で、manualでは実行していない。
- [x] 既存の保存(ゼロ埋めの項目なし)から起動して、ルールが今と同じ名前をつける。ゼロ埋めなしのルールも保存・復元できる。
  - 証拠: 007のunit test(T03。014より前の形のJSONをfixtureにした例9)、Androidエミュレータのmanual(T04 手順4: ゼロ埋めなしの再起動後の復元、2026-09-29 PASS)。
- [x] 001・003・007(と連動する正本)のspec差分を開発者が承認している。
  - 証拠: T01のtask.mdの承認記録。
