# 手動確認: footer の「キャンセル」と、下から出る動き(Androidエミュレータ)

`015:T03` で、browser(「すべて」)と写真・動画の選択画面の footer 左下を「← リネーム画面へ」から**矢印の無い「キャンセル」**にし、「確定」と**同じ幅で横いっぱい**に並べた。置き場所・形(暗い地にシアンの枠と文字)・押したときの意味(選んだものを捨ててリネーム画面へ戻る)は変えていない。

`015:T04` で、2つの選択画面を**下からせり上げて開き、閉じると下へ下げる**動きにした。リネーム画面は動かない。この確認は `T03` と `T04` を同じ build で1回にまとめる。

**対象buildは、`lib/`・`android/` の内容が `T03`・`T04` それぞれの task.md の「Evidence revision」を含む commit と同一のもの**である。branch `asdd/015-screen-switch-placement/T03-footer-cancel-label` の HEAD から build すればこれを満たす。Kotlin は変えていない。**code・dependency・build設定が変わったら、この結果は再利用しない。**

## 準備

- 起動と`flutter run`は`/workspace/docs/development/emulator-verification.md`のとおり。**普段の作業ツリーは branch の移動が不要**(Agent がこの branch にしてある)。hot reload ではなく起動し直す。
- これまでの確認で作った写真・動画をそのまま使う。

## 手順と期待結果

1. 「すべて」を押して browser を開く。
   - 画面が**下からせり上がって**出る。後ろのリネーム画面は縮んだり動いたりしない。
2. ファイルのあるフォルダ(例: `DCIM/Camera`)を開く。
   - footer は左に「キャンセル」(矢印なし、枠付き)、右に「確定」。**2つは同じ幅で横いっぱいに並び、間に不自然な隙間が無い**(attempt 1 の指摘)。いちばん上に帯は無く、header は今までどおり。
   - フォルダを移るときの動きは今までどおり(下から出る動きは付かない)。
3. 1つ選んでから「キャンセル」を押す。
   - 画面が**下へ下がって**消え、リネーム画面へ戻る。一覧は開く前のまま(選んだものは入らない)。
4. もう一度 browser を開いて1つ選び、「確定」を押す。
   - 同じく下へ下がって戻り、選んだものが一覧に入る。
5. もう一度開き、Android のシステムバック(戻るボタンまたは戻るジェスチャ)を押す。
   - 今までどおり選んだものを捨てて browser を閉じ、そのとき下へ下がる。
6. 「写真・動画」で 1〜4 と同じことを行う。
   - footer の並び、開く・閉じる動き、戻り方が browser と同じ。アルバムの絞り込み(下から出るシート)は今までどおり。
7. 気になる点(動きの速さ、文言、ボタンの大きさなど)があれば伝える。
