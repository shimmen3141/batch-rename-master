# 015 画面を切り替えるbuttonの位置を揃える

## 目的

> **2026-10-07 に方針を変えた(下の「人間の決定」)。** 上部の帯は採らず(`T01` 不採用、`T02` 不要)、**footer の配置を保ったまま、左下の「← リネーム画面へ」を矢印なしの「キャンセル」にする**(`T03`)。以下の目的・方針の本文は計画時の記録として残す。

リネーム画面から開く画面(Android の app 内 browser と、写真・動画の選択画面)で、**リネーム画面へ戻る操作を画面の上部に置く**。リネーム画面で別の画面へ移る「別フォルダへ」は上部の帯の右端にあるので、画面を切り替える操作がどちらも上部で見つかるようになる。

**試してみて前の配置のほうが良ければ、採らない。** 新しい配置は task の branch でエミュレータで見比べてもらい、開発者が採ると決めたものだけを `dev` へ入れる。

## 出所

- `specs/product-map.md` の将来候補「画面を切り替えるbuttonの位置を揃える」(`010:T11` の実機確認で開発者が挙げた。2026-10-05)。
- 開発者の決定(2026-10-05): 案A — 戻る側を上部の左へ移し、その button を置く帯は色などでしっかり区別する。取り掛かるのは 010 の後。

## 境界

### 対象

- Android の app 内 browser(`StorageBrowserView`)と、写真・動画の選択画面(`MediaPickerView`)。
- リネーム画面へ戻る button の置き場所と、それを置く帯の見た目。footer の「← リネーム画面へ」を残すか。

### 対象外

- リネーム画面の帯(「別フォルダへ」・場所の表示・歯車)の配置。動かさない。
- browser の header(`←` で上のフォルダへ / 選択中の `×`・題名・ケバブ)と、`008:T38` の操作状態表。**記号も意味も変えない**(2026-10-06 の決定)。
- 戻ったときの振る舞い(決定していない = 一覧は変わらない。004 REQ-008)。置き場所が増えても意味は変えない。
- desktop(OS の選択画面を使うので、この画面が無い)。

## 方針

- **外部振る舞いの仕様(004)は変えない。** 戻る導線の置き場所と見た目は 004 の「自由とする点」(app 内 browser・選択画面の見た目)に入る。戻ると「決定していない」になることは REQ-008 のまま。
- **見比べてから入れる。** `T01` は帯を足し、**footer の「← リネーム画面へ」は残したまま**エミュレータで確かめてもらう。開発者が「前のほうが良い」とすれば、PR を merge せずに閉じ、決定と理由を下の「人間の決定」と product-map の行へ残す(branch は残す)。merge した後で戻したくなったら、その merge commit を `git revert` する PR を出す。
- **戻す単位を小さくする。** 帯を足すこと(`T01`)と、footer の button を外すこと(`T02`)を別の task・別の PR にする。帯は採るが footer は残す、を選べる。
- 2つの画面は同じ部品で帯を描く(片方だけ変わらないように)。
