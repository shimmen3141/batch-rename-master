# 手動確認: アプリを再起動してもルールが復元されること

## 確認すること

「前回のルールを次回起動時に復元する」機能を確認します。開発側のテストでは模擬的な保存先で読み書きを検査していますが、**実際の端末に本当に書けているか**と、**アプリを完全に終了してもデータが残るか**は実機でしか分かりません。

見るのは2方向あります。

- **復元**: 組み立てたルールが、次の起動で戻る。
- **上書き**: ルールを変えたら、次の起動では**新しいほう**が戻る(古いルールが残り続けない)。

2つ目を見ないと、「一度保存したきり更新されない」不具合を見逃します。

## 事前準備

起動手順は[`docs/development/emulator-verification.md`](../../../../docs/development/emulator-verification.md)に従ってください。**branchの移動は不要です。**Agentが対象のbranchとcommitを用意した状態で待ちます。

必要なもの: Android(エミュレータまたは実機)と、Windows desktop build。両方を1回ずつ確認します。

ルールは**見分けがつくもの**にしてください。並びや設定値のどれが崩れても気づけるよう、既定値のままにしないのが要点です。

> ルールA: `元の名前` → `_v` → `連番(開始 7・3桁)` → `作成日時「YYYYMMDD」`
>
> ルールB: `連番(開始 1・2桁)` → `_b` → `元の名前`

## Android

### 1. ルールAを保存する

1. ルールAを組み立てます。
   - 確認: 変更後の名前に反映される(例: `photo_v007<日付>.jpg`)。
   - この時点の並びと設定値を控えておいてください。

### 2. 再読み込みで戻る

1. `flutter run`のコンソールで `R` を押します(アプリを最初から描き直します)。
   - 確認: ルールAがそのまま出る(並び・設定値がすべて一致)。

> これは軽い確認です。アプリ自体は動いたままなので、本当に端末へ保存できている証明にはなりません。次が本番です。

### 3. 完全に終了してから起動しても戻る

1. `flutter run` を `q` で終了するか、アプリを**強制停止**します(設定 → アプリ → このアプリ → 強制停止)。アプリを完全に終わらせてください。
2. アプリを起動し直します。
   - 確認: ルールAが戻っている。並びも設定値(開始7・3桁・`YYYYMMDD`)もすべて一致する。
   - 確認: 変更後の名前も保存前と同じになる。

### 4. 変更してから、もう一度完全に終了して起動する(上書きの確認)

1. ルールを**ルールB**に作り替えます。
   - 確認: 変更後の名前がBの結果に変わる。
2. もう一度アプリを完全終了し、起動し直します。
   - 確認: **ルールBが出る**。ルールAが復活しない。
   - 確認: 順序も設定値もBのまま。

## Desktop (Windows)

1. 同じルールAを組み立てます。
2. アプリのウィンドウを閉じ、完全に終了します(タスクマネージャーに残っていないことを確認)。
3. 起動し直します。
   - 確認: ルールAが戻っている(並び・設定値)。
4. ルールBに作り替え、もう一度完全終了して起動し直します。
   - 確認: ルールBが出る。ルールAが復活しない。

## 補足

保存データが空だったり壊れていたときに空のルールで始まる動きは、開発側のテストで検査済みです。**保存データを壊して試す必要はありません。**

## 結果の伝え方

会話でそのまま教えてください。書式は問いません。戻らなかった場合は、保存前と起動後それぞれの並びと設定値を教えてください。

結果を受け取ったらAgentが`task.md`へ記録し、受け入れ条件を満たしたかreviewします。
